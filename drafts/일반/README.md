# 일반 글 (세법 외)

세법·세무 지식이 들어 있지 않은 글을 쓰는 곳이다. 예: `[생산성]` 도구 설치·사용기, 사무소 소식.

## 세법 글과 다른 점

- **지식 레이어에 넣지 않는다.** `/ingest`·`/lint` 대상이 아니다. 위키 정본(`wiki/topics/`·`wiki/practice/`)에 반영하지 않고, `wiki/business/marketing/` 보관과 `raw/` 복사도 하지 않는다.
- **법률 검증(5단계)을 하지 않는다.** 묻지 않고 건너뛴다(2026-11-16 사용자 결정).
- 세법 내용이 들어가 근거가 필요한 글은 여기에 두지 않는다. 상위 `drafts/`에서 세법 갈래로 쓴다.

## 단계 (상위 README 10단계 기준)

| 단계 | 일반 글에서 |
| --- | --- |
| 1 자료 찾기 | 사용자 기록과 공식 문서. 도구 버전·명령어·요금처럼 바뀌는 사실은 공식 문서로 확인하고 확인일을 적는다 |
| 2 ✋ 독자·분량 | 같음 |
| 3 초안 | fluent-korean 기준. 세법 글의 12구성은 따르지 않아도 된다. 해시태그 20개 규칙은 같다 |
| 4 ✋ 1차 검토 | 같음 |
| 5 법률 검증 | 건너뜀 |
| 6 fluent-korean | 같음 |
| 7 `/humanize-korean` | 같음 |
| 8 위키 역반영 | 건너뜀. 단계마다 `drafts/`만 커밋한다 |
| 9 ✋ 게시와 기록 | 같음. 게시 후 머리말에 `상태: 게시완료`, `게시일`, `게시URL`을 적는다 |
| 10 위키 보관·수집 | 건너뜀. 게시가 끝난 원고는 `일반/게시완료/`로 옮긴다 |

머리말에는 `갈래: 일반`과 `분류`(예: `생산성`)를 적는다.

## [고객안내] 분류 (2026-11-18 사용자 결정)

- 모든 고객에게 공통으로 전하는 안내(자료 전달 방식, 프로그램 연동, 일정 등)는 블로그 [고객안내] 글로 써서 링크로 전달한다.
- 특정 고객 이름·사례·금액은 넣지 않는다. 고객별 메일은 고객 폴더에 따로 두고, 공통 내용은 이 글을 링크한다.
- 세법 판단(공제 요건, 신고 기한 계산 등)이 본문의 중심이면 세법 갈래(`drafts/` 바로 아래)로 쓴다.
