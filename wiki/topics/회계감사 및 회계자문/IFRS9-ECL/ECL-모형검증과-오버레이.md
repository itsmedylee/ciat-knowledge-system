# ECL 모형검증(Validation)과 Overlay

> [!info] 개요
> 전체 공정에서의 위치는 [[기대신용손실-ECL-계산구조]]에 있다. 모델 안에서의 미래전망 반영은 [[ECL-미래전망정보와-다중시나리오]]에 있다.

## 1. 먼저 결론

ECL 공정의 마지막 두 단계이자 **경영진 판단(JUDGMENT)이 가장 크게 개입하는 구간**이다.

| | Validation | Overlay |
|---|---|---|
| 질문 | **모델이 실제로 제대로 작동하는가?** | **모델이 놓친 위험이 남아 있는가?** |
| 성격 | 모델 안의 성능 검증 | 모델 **밖**의 수기 조정 |
| 핵심 위험 | 기준 미달인데 조치 없음 | 근거·해제기준 없는 조정, Double Counting |

## 2. Validation: 만들었다고 끝이 아니다

ECL 모델은 "통계 전문가가 만들었으니까 맞겠지"로 끝낼 수 없다. 회사는 모델 성능을 검증해야 한다.

2023 실무지침이 특히 강조하는 것: **모형 성능에 대한 내부 기준을 만들고, 기준을 충족하지 못할 경우 재조정 또는 재개발할 수 있는 절차를 마련하는 것**이다 `[2023 교재 기준 · 현행 기준 확인 필요]`.

### 2-1. Validation Framework

| 구분 | 내용 |
|---|---|
| **질적 검증** | 모형 설계가 합리적인가 / 데이터가 정확한가 / 보고 및 문제해결 프로세스가 있는가 / 실제 내부업무에서 활용되는가 |
| **양적 검증** | 실제 결과와 예상 결과가 얼마나 일치하는가 / 모델 성능지표가 기준을 통과하는가 / 사후적으로 실제 부도·손실을 잘 예측했는가 |
| **적용 전 Validation** | 모델을 실제 사용하기 전에 검증 |
| **사후 Validation** | 사용 이후 실제 결과와 비교 |

### 2-2. Backtesting의 감각

`[교육용 가상수치]`

| 예측 PD | 실제 부도율 | 판단 |
|---:|---:|---|
| 1.0% | 1.1% | 비교적 가까움 |
| 1.0% | 3.5% | 성능 이상 가능 |
| 1.2% | 3.8% (3년 반복) | **지속적 과소추정 의심** |

A등급 PD를 1%로 예측했는데 실제 10,000명 중 300명(3%)이 부도났고 이런 현상이 지속된다면, 모델이 실제 위험을 과소추정하고 있는 것이다. 여러 등급·세그먼트에서 반복 검증한다.

### 2-3. 기준이 없으면 Validation이 아니다

회사가 **"매년 모델을 검토하고 있습니다. 크게 이상하면 수정합니다."**라고 답한다면, 이것은 Validation이 아니다. 객관적인 **Model Performance Standard**가 없기 때문이다 ([[IFRS9-ECL-03-Final-실전문제-감사실무]] 문제 21).

정의되어야 하는 것:
1. 어떤 지표를 쓰는가 (오차범위 X% 이하, 특정 통계량 기준 이상, 특정 Test 통과 등)
2. 허용범위가 얼마인가
3. **미달 시 어떤 조치를 하는가**

### 2-4. Recalibration vs Redevelopment

| | 상황 | 예 |
|---|---|---|
| **Recalibration** | 모델 **구조는 괜찮은데 파라미터**가 현재 상황과 안 맞음 | 기존 PD 1.2% → 최근 데이터 반영 1.8% |
| **Redevelopment** | 모델 **구조 자체**가 더 이상 적절하지 않음 | 과거엔 금리가 주요 설명변수였으나 산업구조 변화로 설명력 상실 → 새 변수·방법론으로 재개발 |

### 2-5. 감사인이 Validation을 처음부터 다시 하는가

**아니다.** 회사가 해야 할 Validation을 감사인이 전부 대신하는 구조가 아니다. 현실적인 접근은 회사의 **Validation Report를 입수**한 뒤:

1. 회사의 검증 Framework가 적절한지 확인한다
2. 정량·정성 검증이 충분한지 확인한다
3. 검증결과가 회사 기준을 통과했는지 확인한다
4. **일부 핵심 검증을 실제 데이터로 다시 수행**한다

### 2-6. 기준 미달 모델을 그대로 쓰고 있다면

중소기업 Segment PD 모델이 Performance Threshold 미달인데 회사가 "내년 재개발 예정"이라고 한다면, 감사상 질문은 **"기준 미달 모델을 현재 재무제표 ECL에 그대로 사용하는 것이 적절한가?"**다.

회사의 대응을 검토한다: Recalibration / Temporary Adjustment / Overlay / 대체모형.

## 3. Overlay: 모델 밖 조정

### 3-1. 왜 필요한가

ECL 모델이 아무리 정교해도 세상의 모든 위험을 담을 수 없다. 모델을 만들 당시에는 코로나19가 존재하지 않았다. 정부지원으로 원금상환 유예·만기연장이 이루어지면 **겉으로는 연체가 없지만 실제 위험은 증가**했을 수 있고, 기존 PD 모델은 이를 포착하지 못한다.

이때 쓰는 개념이 **Overlay**다.

### 3-2. FLI와 Overlay는 다르다

| | FLI | Overlay |
|---|---|---|
| 대상 | 모델 안에서 합리적으로 예상 가능한 미래 경제상황 | 모델·시나리오가 **충분히 포착하지 못하는** 추가위험 |
| 예 | GDP 감소, 실업률 상승, 금리 상승 | 전염병, 지정학적 충돌, 특수한 정책지원 종료, 특정 취약차주군 위험 |

### 3-3. 적용 방식

교재가 제시하는 방법 `[2023 교재 기준]`:
- 적용 PD 변경
- **Stage 분류 변경**
- 별도 추가충당금 적립

그리고 회사는 **매분기 Overlay 대상과 방법을 재검토**해야 한다.

### 3-4. 가장 큰 위험: Management Bias

Overlay는 필요한 도구이면서 동시에 **경영진 편향이 가장 쉽게 들어오는 영역**이다. 모델 ECL 1,000억원에 "경기가 걱정됩니다"라며 Overlay 300억원을 추가했다면, 감사인은 네 가지를 반드시 묻는다 ([[IFRS9-ECL-03-Final-실전문제-감사실무]] 문제 22):

| # | 질문 |
|---|---|
| 1 | **왜 Overlay가 필요한가**: 기존 모델이 그 위험을 왜 포착하지 못하는가 |
| 2 | **왜 그 금액인가**: 200도 500도 아닌 300억원의 정량화 근거 |
| 3 | **Double Counting은 아닌가**: FLI Downside에 이미 경기침체가 들어 있는데 또 경기침체 Overlay를 넣지 않았는가 |
| 4 | **언제 해제할 것인가**: Monitoring 및 Release 기준 |

추가로: 대상 Exposure는 무엇인가(전체 일괄 vs 특정 산업), 누가 승인했는가(Governance).

### 3-5. 해제하지 않는 것도 오류다

작년 설정한 Overlay의 대상 위험이 올해 상당부분 정상화되었는데 회사가 **"보수적으로 그냥 유지하겠습니다"**라고 한다면, 이것도 문제다.

**IFRS 회계추정의 목적은 보수주의가 아니라 편향되지 않은 적정한 측정이다.** 추가위험이 더 이상 존재하지 않는데 Overlay를 유지하면 ECL을 **과대**계상하게 된다. 경제가 정상화되었는데 관성적으로 유지해서도 안 된다 → [[기대신용손실-ECL-계산구조]] 3-2.

## 4. 헷갈리기 쉬운 부분

| 질문 | 답 |
|---|---|
| 충당금을 많이 쌓을수록 보수적이고 좋은 회계인가? | ❌ 리스크관리에서는 보수성이 중요할 수 있으나, IFRS 회계추정은 **과도하게 낙관적이지도 보수적이지도 않은 적정한 추정**이 핵심이다 `[강사 강조]` |
| Validation 결과가 좋으면 ECL은 신뢰할 만한가? | 모델 성능은 5개 층 중 하나(Model)일 뿐이다 → [[기대신용손실-ECL-계산구조]] 5-1 |
| Overlay가 매년 같은 금액이면? | RED FLAG. 재검토 없이 관성적으로 유지되고 있을 가능성 → [[ECL-감사절차와-체크리스트]] |

## 5. 실무 체크포인트

인터뷰 질문 ([[IFRS9-ECL-01-기초-완벽마스터]] PART 24):
- "최근 모형 Validation 결과 기준을 미달한 모델이 있습니까?"
- "기준 미달 시 recalibration 또는 redevelopment 기준은 무엇입니까?"
- "후보모형 중 최종모형을 선택한 근거는 무엇입니까?"
- "당기 Overlay 대상은 무엇이며, 기존 모델이 그 위험을 반영하지 못한다고 판단한 근거는 무엇입니까?"
- "전분기 대비 Overlay 대상 또는 금액이 변경되었습니까?"

## 6. 핵심 정리

1. **사전에 정한 성능기준이 없으면 Validation이 아니다.**
2. 기준 미달 시 Recalibration / Redevelopment로 연결되는 절차가 있어야 한다.
3. 감사인은 회사 Validation Report를 검토하고 **핵심 검증만 재수행**한다.
4. Overlay는 모델이 못 잡는 위험을 다루는 정당한 도구지만, Management Bias가 가장 쉽게 들어온다.
5. Overlay 4대 질문: 필요성 · 금액 근거 · Double Counting · 해제기준.
6. **쌓는 것만큼 푸는 것도 회계추정이다**. 근거 없는 유지도 오류다.
