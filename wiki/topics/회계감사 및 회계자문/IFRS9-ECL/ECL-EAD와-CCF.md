# ECL의 EAD와 CCF

> [!info] 개요
> 전체 공정에서의 위치는 [[기대신용손실-ECL-계산구조]]에 있다. 대응 개념은 [[ECL-PD-부도확률]]·[[ECL-LGD-부도시손실률]].

## 1. 먼저 결론

**EAD = Exposure at Default = "차주가 부도나는 순간 은행이 얼마만큼 노출되어 있는가"**

**EAD는 현재 장부잔액과 항상 같지 않다.** 정액대출이면 대체로 같지만, **한도성 여신에서는 다르다.**

## 2. 왜 중요한가: 한도대출의 문제

고객에게 100억원 한도가 있고 현재 40억원만 사용 중이다. EAD는 40억원인가?

**반드시 그렇지 않다.** 재무상태가 나빠지는 차주는 **부도 직전에 남은 한도를 추가로 당겨 쓸 가능성이 높다.** 그래서 미사용한도 중 앞으로 얼마나 더 사용할지를 추정해야 한다.

이때 쓰는 것이 **CCF = Credit Conversion Factor(신용환산율)**다.

## 3. 기본 개념: CCF 계산

```
CCF = 부도 전 추가사용액 ÷ 미사용한도
EAD = 현재잔액 + 미사용한도 × CCF
```

`[교육용 가상수치]`: 한도 100억, 현재잔액 40억(미사용 60억), 유사 부도차주의 부도시 잔액 70억:

```
추가사용액 = 70 − 40 = 30
CCF        = 30 ÷ 60 = 50%
EAD        = 40 + 60 × 50% = 70억원
```

> [!note] 참고
> EAD는 **현재 사용한 돈**뿐 아니라 **부도까지 추가로 사용할 것으로 예상되는 돈**까지 고려하는 개념이다.

## 4. 판단 구조: 50%라는 숫자 뒤에 숨은 데이터 정책

CCF 검토에서 흔한 실수는 **결과값만 Recalculate하는 것**이다. 회사가 "과거 부도차주들이 부도 전에 한도를 많이 썼기 때문에 CCF 60%"라고 설명해도, 검증 대상은 60%가 아니라 **60%를 만든 데이터와 정책**이다 ([[IFRS9-ECL-03-Final-실전문제-감사실무]] 문제 6).

| 검토 항목 | 질문 |
|---|---|
| **Population** | CCF 산출에 들어간 차주가 어떤 집단인가? 적용 대상과 위험특성이 일관되는가 |
| **정상시점·부도시점 정의** | 두 시점을 어떻게 정의했는가 |
| **Observation Window** | 부도 직전 몇 개월/몇 년을 관측하는가 |
| **미사용한도 계산** | 한도·약정의 정의가 일관되는가 |
| **추가사용액 데이터** | 부도 전 Drawdown 데이터가 정확·완전한가 |
| **부도 데이터 완전성** | Default Population 누락은 없는가 |
| **Pool/Segment 일관성** | 산출 세그먼트와 적용 세그먼트가 일치하는가 |
| **Negative CCF** | 부도 전 잔액이 **감소**한 경우를 어떻게 처리하는가 (0으로 절사? 그대로 반영?) |

> [!note] 참고
> Negative CCF 처리방식은 결과를 체계적으로 낮추거나 높일 수 있어 별도로 확인할 가치가 있다 `[LLM 해석 — 원본은 항목만 제시]`.

## 5. 헷갈리기 쉬운 부분

| 질문 | 답 |
|---|---|
| EAD = 현재 장부잔액? | ❌ 한도성 상품에서는 더 클 수 있다 |
| 난외(off-balance) 항목은? | 미사용약정·지급보증 등도 신용노출이므로 검토 대상에 포함된다 ([[ECL-감사절차와-체크리스트]] EAD 체크리스트의 "난외 Exposure") `[원문 확인 필요 — 기준서상 적용범위]` |
| CCF는 재계산하면 되는 것 아닌가? | ❌ 결과 재계산만으로는 부족하다 (위 4) |

## 7. 핵심 정리

1. EAD는 "부도 시점의 노출액"이지 "현재 잔액"이 아니다.
2. 한도성 여신에서는 미사용한도 × CCF만큼을 더한다.
3. CCF 검증은 산식이 아니라 **Population·시점 정의·관측기간·데이터 완전성** 검증이다.
4. CCF는 [[ECL-감사절차와-체크리스트]]에서 별도 위험영역으로 관리한다.
