# 7. Key-in 항목 총정리

## 7-1. Key-in이란 무엇이며 왜 필요한가

**정의**: 수식으로 자동 산출되지 않고 작성자가 직접 입력해야 하는 값이다.

**왜 필요한가** `[일반 원칙]`: BSPL 원장은 **잔액과 손익**만 담고 있다. 그러나 현금흐름표는 **거래의 성격**(현금인가 비현금인가, 취득인가 처분인가)을 알아야 한다. 원장에 없는 이 정보를 사람이 판단해 입력하는 것이 Key-in이다.

## 7-3. 요청하신 특정 항목 상세 분석

### ① 원화가지급금 비현금대차 (AL221 = 150,198,747,436) `[파일 확인]`

**왜 이 숫자를 입력하지 않으면 CF가 틀어지는가:**

가지급금은 잔액만 보면 그 안에 무엇이 섞여 있는지 알 수 없다. 예를 들어:
```
가지급금 기초  82 → 기말 1,584 (증감 +1,502억)

이 증가의 실제 내용이:
  Case A: 실제 자금 지출 1,502억  → 영업활동 현금유출 1,502억 ✅
  Case B: 단순 계정 대체 1,502억  → 현금흐름 0 ✅

BS 증감만으로는 A와 B를 구분할 수 없다.
```
작성자는 이 1,502억이 **비현금 대체(Case B)**임을 판단하여 AL221에 입력했다. 입력하지 않으면 영업활동 현금흐름이 **1,502억 과대(또는 과소) 표시**된다.

**검증방법**: N221 = 0 성립 여부. 실제 파일에서 **N221 = 0 확인됨** ✅ `[파일 확인]`

**`[확인 필요]`**: 1,502억을 비현금으로 분류한 근거 조서가 필요하다. 가지급금 상세 내역과 대사되어야 한다.

### ② FVOCI 유가증권 (AO50 = 5,250,571,560) `[파일 확인]`

FVOCI는 취득(Z50 = 10.5조)과 처분(W50 = 10.9조)을 총액으로 파악해야 하는데, 이 총액은 `유가_M` 시트에서 온다. 그런데 **M시트 총액과 BS 증감이 정확히 일치하지 않는 경우**가 발생한다(평가손익, 환율, 상각 등 때문). 그 잔차를 AO50에서 조정한다.

**왜 BS 증감만으론 안 되나**: FVOCI 순증감 −2,922억으로는 21조 규모의 총액 거래를 전혀 알 수 없다.

### ③ 발행금융채 (AI332 = 48,766,421 / P336 = 64,610,415,352) `[파일 확인]`

**P336 (할인할증발행차금 상각 645억)이 특히 중요하다.**

```
사채 발행 시:   현금 980 수령, 액면   824 부채 인식, 차금 20
매기 상각:      (차) 이자비용 5  (대) 사채할인발행차금 5
                → 부채 장부금액이 5 증가하지만 현금 유출 없음
```
이 상각액을 비현금비용으로 가산하지 않으면, 영업활동 현금흐름이 **645억 과소** 표시된다. 동시에 부채 증가를 "신규 발행"으로 오인하면 재무활동도 왜곡된다.

### ④ 보증금 (AI212 = 255,502,000) `[파일 확인]`

미회수 임차보증금에 대한 대손충당금 2.6억. 충당금 설정은 비현금이므로 투자활동 현금흐름에서 제외해야 한다.

### ⑤ 리스부채 (AL394 = 81,769,028,900) `[파일 확인]`

신규 리스 인식분. 리스부채 소계(393행)의 AL 총액은 119,060,849,162이며, 그중 818억이 Key-in이다.

**검증**: `리스부채지급내역_M` 시트의 "리스의 총 현금유출 개별(별도) = 144,249,737,720"이 정산자료 AF393과 **정확히 일치** ✅ `[파일 확인]`

### ⑥ 당기순이익 단수조정 (AO480 = −607,088) `[파일 확인]`

```
P480 (당기순이익) = P481 + P482 + AO480
                  = 1,446,464,774,429 + 0 + (−607,088)
                  = 1,446,464,167,341   ← 전체표 D6과 일치
```

**왜 필요한가**: 하위 항목들을 백만단위로 반올림해 합산하면 실제 당기순이익보다 607,088원 많아진다. 이 누적 오차를 보정하는 값이다.

**지우면 어떻게 되는가**: 당기순이익이 607,088원 과대계상되고 → 영업활동의 출발점이 밀리며 → **기말현금 검증(D239)에서 607,088원의 불일치가 발생한다**. `[파일 확인]`

> [!note] 참고
> **교훈**: 단수조정 셀은 "의미 없는 잔돈"이 아니라 **정합성을 유지하는 필수 장치**다. 함부로 삭제하면 안 된다.

## 7-4. Key-in 관리 원칙 `[논리 추론]`

| 원칙 | 내용 |
|---|---|
| **근거 보관** | 모든 Key-in은 원천자료와 대사된 조서가 있어야 한다 |
| **연도별 이월 검증** | 전기 Key-in과 당기 Key-in의 논리적 연속성 확인 |
| **하드코딩 표시** | 수식 셀과 시각적으로 구분(배경색 등)하여 실수 방지 |
| **검증식 연동** | Key-in 입력 후 반드시 N열 = 0 재확인 |
| **삭제 금지** | 단수조정 셀 포함, 근거 확인 없이 삭제 금지 |
