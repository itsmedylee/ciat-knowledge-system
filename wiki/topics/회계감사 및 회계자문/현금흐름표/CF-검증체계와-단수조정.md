# CF 검증체계와 단수조정

> ⚠️ **[2026-08-20 익명화]** 이 문서가 참조하는 실무 파일의 **실제 기업명은 제거**되었다. `A금융지주`·`은행A`·`은행B`는 치환된 가명이며 실재 법인명이 아니다. 셀 주소·금액·구조는 원본 관측값 그대로이므로 **개념 예시로만** 사용한다.


## 0. 먼저 결론

> **현금흐름표의 품질은 "맞았는가"가 아니라 "왜 맞았는지 설명할 수 있는가"로 판정된다.**
> 검증란이 0인 파일과, 차이의 사유가 셀 옆에 문장으로 적힌 파일은 전혀 다른 물건이다.

그리고 더 위험한 명제 하나:

> **"검증란이 0이 나왔다"는 말을 믿으면 안 된다.** plug 구조에서는 분류 오류가 운전자본 속으로 흡수되어 **검증에 걸리지 않는다**(§3).

## 1. 7단계 검증 맵

기존 [[CF-정산표-원리]] §2-4의 3~4층을 실제 금융지주 파일 기준으로 확장한 것이다.

| Lv | 검증 위치 | 내용 | 목표값 |
|---|---|---|---|
| 1 | **행 검증** (전 계정) | 계정별 배분 합 + 증감 = 0 | 0 |
| 2 | **열 합계** | 각 배분열의 소계 | 활동별 소계와 대사 |
| 3 | **총계** | 자산 = 부채 + 자본, 검증열 총합 | 0 |
| 4 | **활동별 대사** | 영업 소계 = 배분열 합 / 투자 소계 = 유입+유출 / 재무 소계 = 유입+유출 | TRUE |
| 5 | **최종 항등식** | 기초현금 + 영업 + 투자 + 재무 + 환율효과 = 기말현금 | 0 |
| 6 | **공시용 ↔ 정산표** | 공시표의 각 라인이 정산표 셀과 일치 | TRUE |
| 7 | ★ **기말현금 이중산출** | ① 누적식(기초+순증감) vs ② **BS에서 직접** 조회 | **TRUE** |

> **Lv 7이 왜 결정적인가**: 앞의 모든 검증은 정산표 내부의 무결성만 본다. Lv 7만이 **정산표 바깥(원장·BS)과 대조**한다. 정산표가 자기완결적으로 아무리 0이어도, 원장 기말현금과 다르면 틀린 것이다.

## 1.1 검증 아키텍처 6종 (별도 검증파일 기준)

"검증 파일"이라는 개념 자체가 배울 점이다 — **값을 만드는 로직보다 값이 맞는지 판정하는 TRUE/FALSE 셀이 더 많은** 파일.

| 유형 | 판정 대상 |
|---|---|
| ① **합계 검증** | 소계 = 구성항목 합 |
| ② **BS/PL Ref** | 표 간 연결 (CF 당기순이익 ↔ PL, 기초현금 ↔ 전기 BS) |
| ③ ★ **계정과목명 문자열 대사** | **금액이 아니라 계정명 텍스트**를 전기 공시본과 1:1 비교 |
| ④ **주석 내 REF** | 주석 (1)구성내역표 ↔ (2)변동내역표 대사 |
| ⑤ **전기보고서 대사** | 전기 비교표시 금액 = 실제 공시 금액 |
| ⑥ **차이 병기** | TRUE/FALSE와 **차이금액을 함께** 표시 |

## 2. ★ 계정과목명 문자열 대사

```text
O7 = "I. 영업활동으로 인한 현금흐름"   ← 전기 공시 보고서에서 복사한 계정명
B7 = 당기 파일의 계정명
P7 = (O7 = B7) → TRUE
```

**금액이 아니라 계정과목명 텍스트 자체를 전기 보고서와 1:1 대사**한다.

| 잡히는 오류 | 금액 검증으로 잡히는가 |
|---|---|
| 계정명 오탈자 | ❌ |
| 항목 순서 변경 | ❌ |
| 신규 항목 누락 | ❌ |
| **DART XBRL 태깅 깨짐** | ❌ |

> 실제 파일 메모: *"신규계정과목 발생여부 확인 필요(인터뷰, 합계오류 등으로 파악)"* — 작성자가 이 위험을 명시적으로 인식하고 있었다.
> **저비용·고효과 전제조건**: 전기 DART 공시본을 **파일 안에 시트로 통째로 붙여둔다.** 그러면 셀 대 셀 비교가 가능해지고, **전기 수치를 손으로 옮기지 않게 되어** 비교표시 오류가 원천 차단된다.

## 3. ⚠️ plug의 양면성 — 검증이 무력화되는 지점

운전자본 증감을 **잔여(plug)** 로 설계하는 것은 흔하다.

```text
운전자본 증감 = −증감액 − (손익조정 + 이자·배당·법인세 + 투자 + 재무 + 비현금)
```

| 장점 | 치명적 함정 |
|---|---|
| 운전자본을 별도 집계할 필요 없음. **검증열이 자동으로 0** | 분류 누락·오류가 전부 **운전자본 속으로 흡수되어 검증에 걸리지 않는다** |

### 흡수 사례 3종

| 누락 사례 | plug가 흡수한 결과 | 재무제표 왜곡 |
|---|---|---|
| 미지급금 계상 유형자산 취득을 비현금 처리 안 함 | 기타자산 증감 과대 | **투자활동 유출 과대계상** |
| 유효이자 상각액을 비현금열에 안 넣음 | 대출채권 증감 왜곡 | 영업활동 왜곡 |
| 리스개시 시 사용권자산/리스부채 인식 누락 | 기타자산·기타부채 증감 | **투자·재무활동 동시 왜곡** |

> 실화 각색: 무형자산 취득 433억 중 미지급금 계상분을 투자활동 유출로 처리 → 투자활동 현금흐름 433억 과대, 기타부채 증감 433억 과대 → **검증란은 0. 발견 불가.**

### 실무 대응
plug인 계정은 반드시 **별도 명세(주석용 증감표)와 크로스체크**한다. 실제 파일에서는 `상세분석`, `건설중인자산`, `감가상각비명세`, `리스부채만기구조` 시트가 그 역할을 한다.

## 4. 검증식 자체가 깨지는 구조적 위험

| 위험 | 내용 | 개선 |
|---|---|---|
| **코드열이 SUM 범위에 섞임** | 계정코드(예: 5031010103)가 배분열 사이에 있어 SUM에 금액처럼 들어감 → `−SUM(코드열)`로 다시 뺌. **행을 추가하면 이 범위가 자동 확장되지 않아 검증이 소리 없이 깨진다** | 코드열을 텍스트 형식으로 저장하거나 **배분 영역 밖으로 물리적 분리** |
| **수동 나열 검증식** | 펀드 34개의 검증 합계를 `=H12+H58+H106+…` 로 손으로 나열 → 신규 편입 시 **수식 갱신 누락 = 검증 무력화** | `SUMIF(범위,"검증용",…)` 또는 헬퍼열 |
| **하드코딩 plug** | `= … −0.75`, `= ROUND(…) −1` 같은 상수가 박혀 있음 | 반드시 **셀 코멘트로 근거 명시**, 매기 재산정 |
| **외부파일 링크** | `=[1]연결재무상태표!B8` | 링크 끊김 시 `#REF!` → 값 고정 또는 파일 통합 |
| **기말 전용 시트를 분기 파일에 방치** | FALSE 검증셀이 누적되어 **진짜 오류 신호와 구분이 안 됨** | 상태 배너 또는 `IF(기말여부, 검증식, "N/A")` 래핑 |
| **행 오프셋 불일치** | 자회사 시트 템플릿이 어긋나 직접 셀 참조가 밀림 | **계정코드 기반 조회**로 전환 |

## 5. PL Tie-out — 차이를 "설명"하는 문화

조정사항 항목별로 **PL 금액과 대조**하고, 0이 아닌 차이에 **사유 메모를 문장으로** 붙인다.

| 항목 | 차이 | 사유 메모 |
|---|---|---|
| 이자수익 | **0** | — |
| 당기손익-공정가치 금융자산 순손익 | 6,214백만 | "평가손익 및 투자활동 관련 처분손익만 조정하므로 차이 발생" |
| 신용손실충당금전입액 | 8,389백만 | "대출채권매각손익, 상환손익" → 다시 하위 수식으로 7,515백만 설명 |
| 퇴직급여 | −3,575백만 | "자산운용은 100% 확정기여형, 일부 자회사에도 DC형. 시스템은 매출원가에 퇴직급여 포함" |

> 💡 **이것이 배울 최고의 습관**: 차이를 0으로 만들려 억지 조정하지 않고, **왜 다른지를 셀 옆에 문장으로 남긴다.** 감사인·심사역이 가장 먼저 보는 부분이며, 다음 분기 담당자가 바뀌어도 논리가 승계된다.

### 수정전/수정후 비교 열
```text
J열 = 수정전 금액 (직전 버전)
L열 = 당기 − 수정전 (항목별 차이)
M열 = 소계 차이
```
→ **버전 간 변동을 파일 안에서 즉시 확인.** 리뷰 코멘트 반영 누락 방지.

## 6. 단수조정 (천원·백만원 환산)

개별 항목을 각각 반올림하면 **소계가 안 맞는다.** 실무 표준 해법은 **개별 항목에 ±1을 수동 가산**하는 것이다. 이는 편법이 아니라 표준 실무다.

### 6.1 4원칙

| 원칙 | 내용 |
|---|---|
| **어디에 밀어 넣나** | **금액이 큰 항목**에 흡수시킨다 (상대오차 최소화) |
| **몇 개까지 허용되나** | 항목 n개면 최대 ±n/2 수준. 그 이상이면 **원 단위 원본이 틀렸을 가능성** |
| **반드시 남길 것** | 합계검증 셀을 **조정 후에도 TRUE로 유지**. 조정하고 검증을 지우면 **통제 붕괴** |
| ⚠️ **하드코딩 주의** | `−1`은 상수다. **다음 분기에 그대로 두면 오히려 틀린다. 매 분기 재산정 필요** |

### 6.2 2단 조정의 위험
원 단위 CF에서 이미 단수조정을 하고(`>>리스부채의 상환 단수차이 조정`), 천원 단위 표에서 또 조정하는 경우가 있다. **2단 조정은 추적이 어려우므로 근거 메모가 필수**다.

### 6.3 허용오차 정책
비현금거래 차·대 합계가 1원 남거나, 행 검증에 ±0.43이 남는 것은 흔하다. **허용오차 기준(예: ±10원)을 문서화**해 두고, 초과분은 사유를 기재한다. 기준이 없으면 **허용 단수인지 실오류인지 판별할 수 없다.**

## 7. 실무 오류 패턴 카탈로그

작성자가 셀 옆에 남긴 경고 메모가 곧 실무 오류 리스트다.

| 메모 요지 | 시사점 |
|---|---|
| 수익증권 배당금은 IFRS9에서 **채권으로 분류**되어 기타수익 — **배당금 아님** | 계정명만 보고 배당금수취로 보내면 오류 |
| 주식배당금 계정 중 일부는 지분증권 배당수익, 일부는 PEF 출자금 배당으로 기타수익 → **배당수익 해당분만 수기 반영** | ★ **1 COA ≠ 1 성격.** 계정 단위 자동화의 한계 |
| 원화기타당기손익인식증권매매손익이 **모두 투자활동에 대한 것은 아님** → 자회사별 값으로 수령 | **연결 레벨 역산 불가 영역** |
| 외화환산손실·이익은 **통산하여** 표시하므로 부호구분 표시 의미 없음 | 순액 표시 정책 |
| 별도: 차)이익잉여금 / 연결: 차)비지배지분 — 신종미지급배당금 상대계정이 다름 | **별도 vs 연결 분개 상이** |
| 일부 자회사는 100% 확정기여형, 일부는 **매출원가에 포함된 퇴직급여** | 조정사항을 PL 한 줄에서 못 가져오는 이유 |
| ">> 리스부채의 상환 단수차이 조정" | 수동 조정 흔적 → **근거 기록 필요** |

## 8. K-IFRS 1007.44A 재무활동 부채 조정공시

```text
구분     | 기초잔액 | 현금흐름 | 비현금(환율/공정가치/기타) | 기말잔액
발행사채 |  ...     | CF 참조   | 사할차 상각 등             | ...
```

- **별도 표를 유지해야 한다.** 기초 → 현금흐름 → 비현금 → 기말.
- 검증: 조정표 기말잔액 = BS 해당 부채 = 정산표 조회값.
- ⚠️ 관측 파일에서는 이 검증이 **FALSE(361억 차이)** 였고, 원인은 **기초잔액이 하드코딩된 전전기 값일 가능성**으로 추정되었다. `[확인 필요]`
- ⚠️ 재무활동 부채 조정표 시트가 **연차 전용**이면 분기 파일에서 FALSE가 상시 표시된다 → §4 마지막 항목 참조.
