# 2. 현금흐름정산표의 작동 원리

> [!warning] 주의
> ⚠️ **[2026-08-20 익명화]** 이 문서가 참조하는 실무 파일의 **실제 기업명은 제거**되었다. `A금융지주`·`은행A`·`은행B`는 치환된 가명이며 실재 법인명이 아니다. 셀 주소·금액·구조는 원본 관측값 그대로이므로 **개념 예시로만** 사용한다.


## 2-1. 정산표의 근본 아이디어

정산표가 하는 일은 한 문장으로 요약된다. `[일반 원칙]`

> [!note] 참고
> **모든 BS 계정의 잔액 변화(기말−기초)를, 그 변화를 일으킨 원인별로 남김없이 분해한다.**

잔액이 변했다면 반드시 이유가 있다. 이유는 딱 세 종류뿐이다.

| 원인 유형 | 예시 | 현금흐름표 처리 |
|---|---|---|
| ① **현금거래** | 대출 실행, 예금 수취, 자산 취득 | 해당 활동의 현금흐름으로 표시 |
| ② **비현금손익** | 감가상각, 평가손익, 충당금전입 | 손익조정에서 순이익에 가감 |
| ③ **비현금대체** | 계정 재분류, 환산차대, 신규 리스 인식 | 상쇄 처리 (주석 공시 대상) |

이 셋으로 잔액 변화가 **완전히 설명되면** 그 계정은 완결된 것이다. 이를 수식으로 표현한 것이 정산표의 검증열이다.

## 2-2. 정산자료의 열 구조 = 이 파일의 문법 `[파일 확인]`

정산자료 4행·6행에 각 열의 의미와 **부호**가 정의되어 있다. 이것이 정산표를 읽는 문법이다.

| 열 | 6행 그룹명 | 4행 부호 정의 | 실질 의미 |
|---|---|---|---|
| **J** | 전기말잔액 | (건들기 X) | 기초 잔액 |
| **K** | 당기말잔액 | BSPL로 수정 | 기말 잔액 |
| **M** | 당기증감 | — | `= K − J` |
| **P** | 현금의 유출이 없는 비용 가산 | 현금증가 | 감가상각비·평가손·충당금전입 등 |
| **S** | 현금의 유입이 없는 수익 차감 | 현금감소 | 평가익·충당금환입·상각 등 |
| **U** | 자산부채증감 | 현금증가 | 영업활동 자산·부채 순증감 |
| **W** | 유입(자산처분) | 현금증가 | 투자활동 처분 총액 |
| **Z** | 유출(자산취득) | 현금감소 | 투자활동 취득 총액 |
| **AC** | 유입(부채차입) | 현금증가 | 재무활동 조달 총액 |
| **AF** | 유출(부채상환) | 현금감소 | 재무활동 상환 총액 |
| **AI** | 비현금거래 차변 | 현금감소 | 비현금 대체 (차변) |
| **AL** | 비현금거래 대변 | 현금증가 | 비현금 대체 (대변) |
| **AO** | 단수 조정 | — | 백만단위 반올림 잔차 보정 |
| **N** | **검증** | — | **아래 항등식 = 0** |

## 2-3. 핵심 항등식: N열 검증 `[파일 확인]`

```
N = M + P − S + U + W − Z + AC − AF − AI + AL = 0
```

정산자료 N4 헤더에 `당기증감(현금감소로부호맞춤)+현금증가-현금감소=0`이라고 명시되어 있다.

**이 식이 의미하는 바:**
- 좌변의 `M`(잔액 변화)이
- 우변의 모든 원인(P·S·U·W·Z·AC·AF·AI·AL)으로 **완전히 설명되면** 0이 된다.
- 0이 아니면 → **설명되지 않은 변화가 남아 있다** = 해당 계정 분석 미완료

> [!note] 참고
> **실무 활용**: N열이 0이 아닌 행부터 찾아 들어가면 오류를 계정 단위로 특정할 수 있다. 이것이 정산표 방식의 최대 강점이다.

## 2-4. 3층 검증 체계 `[파일 확인]`

이 파일은 세 개 층위에서 검증한다. 상위로 갈수록 강력하다.

| 층위 | 위치 | 검증 내용 | 현재 상태 |
|---|---|---|---|
| **① 계정별** | 정산자료 N열 (각 행) | 계정별 대차 = 0 | 대부분 0 |
| **② 대차총계** | 정산자료 J513/K513/M513 | 자산 = 부채 + 자본 | **True** ✅ |
| **③ 소계별** | 정산자료 P516 / S516 | 비현금 비용·수익이 전체표와 일치 | S516에 15,658,562 잔존 ⚠️ |
| **④ 최종** | 전체표 D852 / 흐름자료 D238 | **계산 기말현금 = 원장 기말현금** | **True (차이 0)** ✅ |

**④가 가장 중요하다.** `[일반 원칙]`

```
기초현금 + 영업CF + 투자CF + 재무CF + 환율효과 = 기말현금 = 원장 잔액
```

이 등식이 성립하면 **전체 현금흐름표가 정확하다는 최종 증명**이 된다. 아무리 개별 계정을 잘 맞춰도 이게 안 맞으면 어딘가 틀린 것이고, 반대로 이게 맞으면 큰 틀에서 검증된 것이다.

파일에서 실제 확인: `[파일 확인]`
- 전체표 D851 (계산 기말현금) = 23,189,858,812,430
- 전체표 D853 (원장 = 정산자료!K8) = 23,189,858,812,430
- D852 검증 = **True**

## 2-5. 정산표 작성 순서 (실무 프로세스) `[논리 추론]`

파일 구조로부터 역산한 실제 작업 순서:

```
Step 1. 계정 세로 배열
        BS 전 계정을 계정코드 순으로 세로 나열 (정산자료 각 행)

Step 2. 잔액 입력 (자동)
        J열 ← BSPL_2025.4Q (SUMIFS)
        K열 ← BSPL_2026.2Q (SUMIFS)
        M = K − J 자동 계산

Step 3. 비현금손익 매핑 (자동)
        P열(비용)·S열(수익) ← BSPL 손익계정 SUMIFS

Step 4. 현금거래 총액 배분 (M시트 참조)
        W/Z(투자), AC/AF(재무) ← 유형자산_M, 유가_M, 사채_M 등

Step 5. 비현금대체 처리 (M시트 + Key-in)
        AI/AL ← M해외사업환산차대, 수기입력

Step 6. N열 검증 → 0이 아닌 행 원인 규명 → Step 3~5 반복

Step 7. 전체표로 CF 코드별 집계

Step 8. 백만단위 환산 + 단수조정(AO열, R열)

Step 9. 최종 검증: 기말현금 = 원장
```

## 🔷 금융지주 연결 사례 (A금융지주 FY25 1Q)

> [!quote] 출처
> 출처: [[현금흐름표_정산표_학습레포트-소스요약]]. 위 2-1~2-5는 **은행 별도 / 2026 2Q** 파일 기준이고, 이 절은 **금융지주 연결 / FY25 1Q** 파일 기준이다. 같은 개념에 대한 **독립적 제2 관측**이다.

### 2-6. ⚠️ 열 문자를 외우면 안 되는 이유: 두 파일의 열 배치가 다르다

| 역할 | 은행 별도 파일 | 금융지주 연결 파일 |
|---|---|---|
| 기초/기말/증감 | J / K / M | D / E / F |
| 비현금 비용가산 | P | L |
| 비현금 수익차감 | S | O |
| 자산·부채 증감 | U | P |
| 이자·배당·법인세(현금) | (별도 열 없음) | R / S / T / U |
| 투자 유입/유출 | W / Z | W / Y |
| 재무 유입/유출 | AC / AF | AA / AC |
| 비현금 차변/대변 | AI / AL | AE / AG |
| **검증열** | **N** | **H** |

> [!note] 참고
> **교훈**: 정산표를 배울 때 외울 것은 열 문자가 아니라 **"이 열이 담는 역할"** 이다. 파일이 바뀌면 문자는 전부 바뀐다.

금융지주 파일의 지배 항등식:
```text
ΔBS(F) = −[ 손익조정(L+O) + 운전자본증감(P)
           + 이자수취(R) + 이자지급(S) + 배당수취(T) + 법인세납부(U)
           + 투자유입(W) + 투자유출(Y) + 재무유입(AA) + 재무유출(AC)
           + 비현금(AE+AG) ]

구현: H열 = SUM(I:AG) + F = 0
```
> [!note] 참고
> **왜 `+F`인가**: 자산 증가(F>0)는 현금 유출(−)이므로 배분열의 합이 `−F`가 되어야 한다. 따라서 `합 + F = 0`.

### 2-7. 파일 아키텍처 4계층: 연결에서 필수

```text
[1층] 원천 TB (매트릭스)      계정코드 | 계정명 | Lvl | 법인별 잔액
                              (지주·은행·증권·캐피탈·저축은행·구조화기업 33개·998:연결조정)
          │ VLOOKUP(계정코드, 정산표, 법인열번호, FALSE)
          ▼
[2층] 법인별 CF정산표         동일 템플릿 10개 + 펀드CF(세로 반복) → 펀드합계
          │ 셀 단위 참조
          ▼
[3층] 연결현금흐름정산표      + 상세분석(별도합산 vs 연결 차이 원인)
          │
          ▼
[4층] CF공시용                2기 비교표 + 수정전/수정후 대사
```

### 2-8. 확장 가능 설계 5기법

| 기법 | 구현 | 왜 중요한가 |
|---|---|---|
| **열번호의 셀 파라미터화** | `B1=70` 같은 셀에 VLOOKUP 열번호를 저장하고 전 시트가 그 셀을 참조 | 법인 1개 추가 시 **셀 2개만 수정**. 하드코딩이면 수천 개 수식 수정 |
| **열번호 자동산출(진화형)** | `INDEX($F$4:$XFD$4, MATCH(법인명, $F$5:$XFD$5,))` | 법인명(헤더 문자열)으로 열번호를 역산 → **열 순서가 바뀌어도 안 무너짐** |
| **전기 TB 병존** | 전기말 정산표 시트를 같은 파일에 유지 | 기초잔액을 손으로 옮기지 않음 = **기초잔액 오류 원천 차단** |
| **템플릿 동일화** | 자회사 시트를 행번호까지 동일하게 | 연결시트에서 직접 셀 참조 가능 |
| **버전·기준일 파일명** | `v1_0_0507`, `v1_4_대손준비금수정`, `_2503` | 결산 리뷰 이력 추적. **감사대응 시 필수** |

> [!warning] 주의
> ⚠️ **관측된 위험**: 실제로는 자회사 시트 간 행 오프셋이 일정하지 않아 **템플릿 동일화의 이점이 이미 일부 훼손**되어 있었다. 신규 계정 추가 시 참조 어긋남이 발생할 수 있다. → **계정코드 기반 조회로 전환**하기를 권한다.

### 2-9. ⚠️ 운전자본 = plug 설계의 함정

금융지주 파일은 운전자본 증감(P열)을 **계산값이 아니라 잔여(plug)** 로 둔다. 편리하지만 **분류 누락·오류가 전부 운전자본 속으로 흡수되어 검증에 걸리지 않는다.**

상세 및 흡수 사례 3종은 [[CF-검증체계와-단수조정]] §3 참조. 이 문서 §2-4의 3층 검증도 그곳에서 **7단계로 확장**된다.
