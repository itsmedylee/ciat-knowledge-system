# 1. 은행 현금흐름표 전체 구조

## 1-1. 왜 은행 현금흐름표는 어려운가

제조업 현금흐름표는 "영업(본업) + 투자(설비) + 재무(자금조달)"라는 직관이 통한다. 그런데 은행은 **돈 자체가 상품**이다. 대출을 내주는 것이 설비투자가 아니라 본업이고, 예금을 받는 것이 차입이 아니라 본업이다. 이 지점에서 일반적 직관이 무너진다.

여기서 은행 CF의 첫 번째 원칙이 나온다. `[일반 원칙]`

> **금융회사의 영업활동 범위는 제조업보다 훨씬 넓다. 대출채권·예수부채·단기매매증권처럼 "제조업이라면 투자·재무활동일 것"이 은행에서는 영업활동이 된다.**

이유는 K-IFRS 제1007호가 활동 분류의 기준을 **"기업의 주요 수익창출활동인가"**에 두기 때문이다. 대출·예금은 은행의 주요 수익창출활동 그 자체이므로 영업활동이다.

## 1-2. 은행 CF 공시 양식의 3단 구조 `[파일 확인]`

제공 파일의 `공시용 CF` 시트를 보면 은행 표준 양식이 명확히 드러난다. (단위: 백만원)

```
Ⅰ. 영업활동으로부터의 현금흐름                     8,772,898
   1. 당기순이익                                  1,446,464
   2. 손익조정사항                                  741,894   ← 비현금손익 제거 (14개 항목)
   3. 자산·부채의 증감                             6,584,540   ← 영업용 자산·부채 순증감 (9개 항목)

Ⅱ. 투자활동으로부터의 현금흐름                    -2,739,609   ← 총액표시 (처분/취득 각각)
Ⅲ. 재무활동으로부터의 현금흐름                    -1,982,629   ← 총액표시 (증가/감소 각각)
Ⅳ. 외화표시 현금및현금성자산에 대한 환율변동효과       364,098   ← 별도 표시 (현금흐름 아님)
Ⅴ. 현금및현금성자산의 순증감 (I+II+III)            4,414,758
Ⅵ. 기초 현금및현금성자산                          18,695,922
   기말 현금및현금성자산                          23,110,680
```

이 구조에서 반드시 기억할 두 가지:

**(1) 영업활동의 3단 구조가 곧 간접법의 전부다**
```
당기순이익  →  ± 손익조정(비현금손익 제거)  →  ± 자산·부채 증감  =  영업활동 현금흐름
```
- **2단(손익조정)**: PL에 있지만 현금이 안 오간 손익을 걷어낸다 (감가상각비, 평가손익, 충당금전입 등)
- **3단(자산부채증감)**: BS 변화 중 영업 관련분을 반영한다 (대출채권·예수부채 증감 등)

**(2) Ⅳ 환율변동효과는 "현금흐름이 아니다"**
Ⅴ 순증감 계산식이 `(I + II + III)`로 **Ⅳ를 제외**하고 있다는 점에 주목하라. 환율효과는 현금이 오간 것이 아니라 기존 외화현금의 원화 환산액만 바뀐 것이므로, 3대 활동과 **구분 표시**한다. `[일반 원칙]` (K-IFRS 제1007호 문단 28)

# 2. 현금흐름정산표의 작동 원리

## 2-1. 정산표의 근본 아이디어

정산표가 하는 일은 한 문장으로 요약된다. `[일반 원칙]`

> **모든 BS 계정의 잔액 변화(기말−기초)를, 그 변화를 일으킨 원인별로 남김없이 분해한다.**

잔액이 변했다면 반드시 이유가 있다. 이유는 딱 세 종류뿐이다.

| 원인 유형 | 예시 | 현금흐름표 처리 |
|---|---|---|
| ① **현금거래** | 대출 실행, 예금 수취, 자산 취득 | 해당 활동의 현금흐름으로 표시 |
| ② **비현금손익** | 감가상각, 평가손익, 충당금전입 | 손익조정에서 순이익에 가감 |
| ③ **비현금대체** | 계정 재분류, 환산차대, 신규 리스 인식 | 상쇄 처리 (주석 공시 대상) |

이 셋으로 잔액 변화가 **완전히 설명되면** 그 계정은 완결된 것이다. 이를 수식으로 표현한 것이 정산표의 검증열이다.

## 2-2. 정산자료의 열 구조 = 이 파일의 문법 `[파일 확인]`

정산자료 4행·6행에 각 열의 의미와 **부호**가 정의되어 있다. 이것이 정산표를 읽는 문법이다.

| 열 | 6행 그룹명 | 4행 부호 정의 | 실질 의미 |
|---|---|---|---|
| **J** | 전기말잔액 | (건들기 X) | 기초 잔액 |
| **K** | 당기말잔액 | BSPL로 수정 | 기말 잔액 |
| **M** | 당기증감 | — | `= K − J` |
| **P** | 현금의 유출이 없는 비용 가산 | 현금증가 | 감가상각비·평가손·충당금전입 등 |
| **S** | 현금의 유입이 없는 수익 차감 | 현금감소 | 평가익·충당금환입·상각 등 |
| **U** | 자산부채증감 | 현금증가 | 영업활동 자산·부채 순증감 |
| **W** | 유입(자산처분) | 현금증가 | 투자활동 처분 총액 |
| **Z** | 유출(자산취득) | 현금감소 | 투자활동 취득 총액 |
| **AC** | 유입(부채차입) | 현금증가 | 재무활동 조달 총액 |
| **AF** | 유출(부채상환) | 현금감소 | 재무활동 상환 총액 |
| **AI** | 비현금거래 차변 | 현금감소 | 비현금 대체 (차변) |
| **AL** | 비현금거래 대변 | 현금증가 | 비현금 대체 (대변) |
| **AO** | 단수 조정 | — | 백만단위 반올림 잔차 보정 |
| **N** | **검증** | — | **아래 항등식 = 0** |

## 2-3. 핵심 항등식 — N열 검증 `[파일 확인]`

```
N = M + P − S + U + W − Z + AC − AF − AI + AL = 0
```

정산자료 N4 헤더에 `당기증감(현금감소로부호맞춤)+현금증가-현금감소=0`이라고 명시되어 있다.

**이 식이 의미하는 바:**
- 좌변의 `M`(잔액 변화)이
- 우변의 모든 원인(P·S·U·W·Z·AC·AF·AI·AL)으로 **완전히 설명되면** 0이 된다.
- 0이 아니면 → **설명되지 않은 변화가 남아 있다** = 해당 계정 분석 미완료

> **실무 활용**: N열이 0이 아닌 행부터 찾아 들어가면 오류를 계정 단위로 특정할 수 있다. 이것이 정산표 방식의 최대 강점이다.

## 2-4. 3층 검증 체계 `[파일 확인]`

이 파일은 세 개 층위에서 검증한다. 상위로 갈수록 강력하다.

| 층위 | 위치 | 검증 내용 | 현재 상태 |
|---|---|---|---|
| **① 계정별** | 정산자료 N열 (각 행) | 계정별 대차 = 0 | 대부분 0 |
| **② 대차총계** | 정산자료 J513/K513/M513 | 자산 = 부채 + 자본 | **True** ✅ |
| **③ 소계별** | 정산자료 P516 / S516 | 비현금 비용·수익이 전체표와 일치 | S516에 15,658,562 잔존 ⚠️ |
| **④ 최종** | 전체표 D852 / 흐름자료 D238 | **계산 기말현금 = 원장 기말현금** | **True (차이 0)** ✅ |

**④가 가장 중요하다.** `[일반 원칙]`

```
기초현금 + 영업CF + 투자CF + 재무CF + 환율효과 = 기말현금 = 원장 잔액
```

이 등식이 성립하면 **전체 현금흐름표가 정확하다는 최종 증명**이 된다. 아무리 개별 계정을 잘 맞춰도 이게 안 맞으면 어딘가 틀린 것이고, 반대로 이게 맞으면 큰 틀에서 검증된 것이다.

파일에서 실제 확인: `[파일 확인]`
- 전체표 D851 (계산 기말현금) = 23,189,858,812,430
- 전체표 D853 (원장 = 정산자료!K8) = 23,189,858,812,430
- D852 검증 = **True**

## 2-5. 정산표 작성 순서 (실무 프로세스) `[논리 추론]`

# 3. 영업·투자·재무활동 분류 논리

## 3-1. 분류의 근본 기준 `[일반 원칙]`

K-IFRS 제1007호의 분류 기준:

| 활동 | 정의 | 은행에서의 의미 |
|---|---|---|
| **영업활동** | 주요 수익창출활동 및 투자·재무활동이 아닌 활동 | 여신·수신·유가증권 매매 등 **본업 전체** |
| **투자활동** | 장기성 자산 및 현금성자산에 속하지 않는 투자자산의 취득·처분 | **투자 목적** 유가증권, 유형·무형자산, 지분법자산 |
| **재무활동** | 자본과 차입금의 크기·구성 변동 | 사채·차입금·배당 등 **자금조달** |

## 3-2. 왜 은행에서는 영업활동 범위가 넓어지는가

### 핵심 논리
> **"그 자산·부채가 은행의 수익창출 그 자체인가, 아니면 수익창출을 위한 수단인가"**

| 항목 | 제조업 | 은행 | 이유 |
|---|---|---|---|
| **대출채권** | (해당 없음) | **영업활동** | 이자수익 창출의 본체. 제조업의 매출채권에 해당 |
| **예수부채** | (해당 없음) | **영업활동** | 예금은 차입이 아니라 은행의 상품. 예대마진의 원천 |
| **단기매매증권(FVPL)** | 투자활동 | **영업활동** | 트레이딩 = 은행의 수익창출활동 |
| **투자증권(FVOCI/AC)** | 투자활동 | **투자활동** | 장기 보유·유동성 관리 목적 |
| **차입부채·사채** | 재무활동 | **재무활동** | 자금조달 수단 |
| **파생상품** | 상황별 | **분리** | 매매목적→영업, 위험회피→투자/재무 |

### 파일에서의 실제 분류 `[파일 확인]`

`공시용 CF` 3. 자산·부채의 증감(영업활동)에 포함된 항목:
```
(1) 당기손익인식금융자산  -1,569,161   ← FVPL: 영업활동
(2) 파생금융상품             99,981   ← 매매목적 파생: 영업활동
(3) 대출채권             -6,463,399   ← 영업활동
(5) 기타자산            -13,881,038
(7) 예수부채             12,306,433   ← 영업활동
(9) 기타부채             15,936,049
```

투자활동(Ⅱ)에 포함된 항목:
```
(3) 투자금융상품의 처분    16,319,572   ← FVOCI + AC: 투자활동
(4) 투자금융상품의 취득   -19,072,716
(5) 지분법적용자산의 처분      88,867
(7) 유형자산의 처분            9,967
```

→ **같은 "유가증권"인데 FVPL은 영업활동, FVOCI·AC는 투자활동**으로 갈린다. 이것이 은행 CF 분류의 핵심 분기점이다.

## 3-3. 파생상품의 3분류 — 가장 어려운 부분 `[파일 확인]`

파생상품은 **보유 목적에 따라 세 갈래**로 나뉜다. 이 파일이 정확히 그렇게 처리하고 있다.

| 파생 유형 | 정산자료 행 | 분류 | 근거 |
|---|---|---|---|
| **매매목적 파생** | 183~186 | **영업활동** (자산부채증감 U열) | 트레이딩 = 수익창출활동 |
| **공정가치위험회피 파생** | 187~191 | **투자활동**(W/Z) + **재무활동**(AF) | 회피대상 자산·부채의 성격을 따름 |
| **현금흐름위험회피 파생** | 192~195 | **재무활동** (AC/AF) | 주로 조달 관련 위험 회피 |

전체표에서의 실제 매핑: `[파일 확인]`
```

D732 공정가치위험회피파생자산 (순감소)  = 정산자료!W189          → 투자활동 유입

```

> **WHY**: 위험회피회계에서 파생상품은 그 자체가 목적이 아니라 **회피대상(hedged item)의 위험을 상쇄**하기 위한 수단이다. 따라서 회피대상이 투자자산이면 투자활동, 조달부채면 재무활동으로 분류하는 것이 경제적 실질에 부합한다. `[일반 원칙]`

## 4-2. 대출채권 — 은행 CF의 심장

### A. 계정의 경제적 실질

은행의 **주된 수익창출 자산**이다. 제조업의 매출채권과 형태는 비슷하지만 성격이 근본적으로 다르다.

| 구분 | 제조업 매출채권 | 은행 대출채권 |
|---|---|---|
| 발생 원인 | 매출의 부산물 (외상판매) | **그 자체가 상품** (여신 실행) |
| 수익 인식 | 매출액 인식 시점 | 기간 경과에 따른 **이자수익** |
| CF 분류 | 영업활동 (매출채권 증감) | **영업활동** (대출채권 증감) |
| 규모 | 총자산의 일부 | **총자산의 대부분** (파일: 350조 / 비중 압도적) |

> **WHY 영업활동인가**: 대출 실행은 은행의 주요 수익창출활동이다. 제조업이라면 "자금 대여 = 투자활동"이지만, 은행에게 대출은 재고자산을 파는 것과 같은 본업이다. `[일반 원칙]`

### B. 일반적인 회계처리

```
① 대출 실행 (현금거래)
   (차) 대출채권        824    (대) 현금          824

② 이자 수취 (현금거래)
   (차) 현금            50     (대) 이자수익       50

③ 미수이자 인식 (비현금)
   (차) 미수수익        10     (대) 이자수익       10

④ 대손충당금 설정 (비현금)
   (차) 대손상각비      30     (대) 대손충당금      30

⑤ 대손확정 상각 (비현금 — 총액 감소)
   (차) 대손충당금      20     (대) 대출채권       20

⑥ 원금 회수 (현금거래)
   (차) 현금          300     (대) 대출채권      300
```

### C. 현금이 움직이는 거래
- 대출 실행 (현금 유출)
- 원금 회수 (현금 유입)
- 이자 수취 (현금 유입)

### D. 비현금거래
- **대손충당금 설정/환입** (④)
- **대손확정 상각** (⑤) — 장부금액은 줄지만 현금은 안 움직임
- **현재가치할인차금 상각**
- **외화대출의 환율변동**
- **연체이자 자본화 / 재약정에 따른 계정 대체**

### E. BS 증감을 그대로 현금흐름으로 쓸 수 있는가?
**일부 조정 필요** ⚠️

이유: 대출채권 장부금액 변화에는 ①실제 현금 대출/회수 외에 ②대손상각 ③충당금 변동 ④환율변동 ⑤계정대체가 섞여 있다.

**예시로 보는 오류:**
```
기초 대출채권   824
당기 신규대출  +500 (현금유출)
당기 원금회수  -300 (현금유입)
대손상각      -50  (비현금)
기말 대출채권    948

BS 증감 =   948 -   824 = +150
→ 이걸 그대로 쓰면 "현금 150 유출"로 표시됨 ❌

실제 현금흐름 = -500 + 300 = -200 (현금 200 유출) ✅
차이 50 = 대손상각(비현금)
```
→ **조정 안 하면 현금흐름이 50만큼 과소 표시된다.**

### F. 필요한 현금흐름 조정 (Bridge)

```
기말 대출채권 (총액)
- 기초 대출채권 (총액)
= BS 증감
  + 대손상각(제각)액              ← 비현금 감소분 복원
  ± 대손충당금 증감                ← 비현금
  ± 현재가치할인차금 상각          ← 비현금
  ± 외화대출 환율변동효과          ← 비현금
  ± 계정대체 (정상↔부실 재분류)   ← 비현금
= 실제 대출 순현금흐름
```

### G. 현금흐름표 분류
**영업활동 → 3. 자산·부채의 증감 → (3) 대출채권**
파일 확인: `공시용 CF` 23행 `(3) 대출채권 -6,463,399` (백만원) `[파일 확인]`

### H. 현재 정산표에서의 처리 `[파일 확인]`

5. **부실채권 매각**: 대량 매각 시 투자활동으로 볼 것인지 영업활동으로 볼 것인지 판단 필요. `[확인 필요]`

## 4-3. 예수부채 — 은행 CF의 또 다른 심장

### A. 계정의 경제적 실질

고객이 맡긴 예금. **은행 입장에서 부채**인 이유는 언제든 반환 의무가 있기 때문이다. 그러나 일반적인 차입금과는 성격이 완전히 다르다.

| 구분 | 일반 차입금 | 예수부채 |
|---|---|---|
| 목적 | 자금조달 | **상품 판매** (수신 = 은행의 서비스) |
| 상대방 | 금융기관·투자자 | 불특정 다수 고객 |
| 수익 구조 | 이자 지급 (비용) | 예대마진의 원천 (**수익창출 기반**) |
| CF 분류 | **재무활동** | **영업활동** |

> **WHY 영업활동인가**: 예금 수취는 은행의 핵심 영업 그 자체다. 예금을 받아 대출로 운용하여 예대마진을 얻는 것이 은행의 비즈니스 모델이므로, 예수부채 증감은 영업활동이다. `[일반 원칙]`
>
> 이 지점이 제조업 회계사가 은행 CF를 볼 때 가장 크게 혼동하는 부분이다. "부채가 늘었으니 재무활동 아닌가?"라는 직관이 틀린다.

### B. 일반적인 회계처리

```
① 예금 수취 (현금거래)
   (차) 현금          824    (대) 예수부채        824

② 이자 지급 (현금거래)
   (차) 이자비용       30     (대) 현금            30

③ 미지급이자 인식 (비현금)
   (차) 이자비용       10     (대) 미지급비용       10

④ 예금 지급 (현금거래)
   (차) 예수부채      500     (대) 현금           500

⑤ 외화예금 환율변동 (비현금)
   (차) 외화환산손실    20     (대) 예수부채        20
```

### C~D. 현금거래 vs 비현금거래
- **현금**: 예금 입금, 예금 출금, 이자 지급
- **비현금**: 미지급이자 발생, 외화예금 환율변동, 이자의 원금 전입(자동 재예치)

### E. BS 증감을 그대로 쓸 수 있는가?
**일부 조정 필요** ⚠️ (단, 대출채권보다는 조정폭이 작음)

주된 조정 대상은 **외화예금의 환율변동효과**와 **미지급이자**다.

### F. 필요한 현금흐름 조정 (Bridge)

```
기말 예수부채
- 기초 예수부채
= BS 증감
  ∓ 외화예금 환율변동효과          ← 비현금 (환율효과로 별도 분리)
  ∓ 미지급이자 증감                ← 비현금
  ∓ 이자 원금전입 (비현금 재예치)  ← 비현금
= 예수부채 순현금흐름 (영업활동)
```

### G. 현금흐름표 분류
**영업활동 → 3. 자산·부채의 증감 → (7) 예수부채**
파일 확인: `공시용 CF` 27행 `(7) 예수부채 12,306,433` (백만원) `[파일 확인]`

### H. 현재 정산표에서의 처리 `[파일 확인]`
정산자료 291행이 예수부채 소계 행이다. 순증감이 U열로 흘러가 영업활동에 반영된다.

### I. 검토 시 주의사항

1. **환율변동효과 분리**: 외화예금 비중이 큰 은행일수록 중요하다. 환율변동으로 인한 원화 장부금액 증가를 "예금 유치"로 오인하면 영업활동이 부풀려진다.
2. **순액표시의 정당성**: 예수부채는 회전이 매우 빈번하므로 순액표시가 허용된다(K-IFRS 1007호 문단 24). 총액으로 표시하면 수백조 규모가 되어 정보가치가 떨어진다. `[일반 원칙]`
3. **양도성예금증서(CD)**: 예수부채인지 발행금융채인지 분류 확인 필요. 분류에 따라 영업/재무활동이 갈린다. `[확인 필요]`
4. **이자 지급액 별도 공시**: K-IFRS는 이자 지급액을 별도 공시하도록 요구한다. 파일 `공시용 CF` 14행에 `(9) 순이자손익 105,651`이 손익조정 항목으로 존재한다 `[파일 확인]`.

## 4-5. 유가증권 ② FVOCI (기타포괄손익-공정가치측정)

### A. 계정의 경제적 실질
**장기 투자 및 유동성 관리 목적**으로 보유. 평가손익이 당기손익이 아닌 **기타포괄손익(OCI, 자본)**으로 간다는 점이 결정적 차이다.

### B. 일반적인 회계처리
```

   (차) FVOCI금융자산    824    (대) 현금          824
② 공정가치 평가 (비현금, OCI!)
   (차) FVOCI금융자산    50     (대) 기타포괄손익   50   ← 당기순이익 아님!
③ 처분 (현금)
   (차) 현금            907    (대) FVOCI금융자산   865
                                (대) 처분이익        50
```

### C~D. 현금거래 vs 비현금거래
- **현금**: 취득, 처분
- **비현금**: **공정가치 평가손익(OCI)**, 환율변동, 손상, 현재가치할인차금 상각

### E. BS 증감 사용 가능성
**불가능** ❌ — 반드시 총액 조정 필요

**WHY**: 두 가지 이유가 겹친다.
1. 투자활동은 **총액표시**가 원칙이므로 취득액과 처분액을 각각 파악해야 한다. BS 순증감으로는 총액을 알 수 없다.
2. 평가손익이 **OCI(자본)**로 가므로 당기순이익에 없다. 따라서 **손익조정 대상이 아니면서도** 장부금액은 변화시킨다.

> **핵심 함정**: FVPL 평가손익은 당기순이익에 있으므로 손익조정에서 제거해야 하지만, **FVOCI 평가손익은 당기순이익에 애초에 없으므로 제거 대상이 아니다.** 간접법은 당기순이익에서 출발하므로, 순이익에 없는 것을 빼면 오히려 틀린다. `[일반 원칙]`

### F. Bridge (Roll-forward)

```
기초 FVOCI 장부금액
+ 현금 취득액                    ← 투자활동 유출 (Z열)
- 현금 처분액 (장부금액 기준)     ← 투자활동 유입 (W열)
+ 공정가치 평가손익 (OCI)         ← 비현금 (당기순이익 아님)
+ 환율변동효과                    ← 비현금
+ 현재가치할인차금 상각            ← 비현금
- 손상차손                        ← 비현금
= 기말 FVOCI 장부금액
```

## 4-9. 리스부채 / 사용권자산

### A. 계정의 경제적 실질
K-IFRS 제1116호 도입으로 대부분의 리스가 자산·부채로 인식된다. 은행은 영업점 임차가 많아 리스 규모가 크다.

### B. 회계처리
```
① 리스 개시 (비현금!)
   (차) 사용권자산      824    (대) 리스부채       824   ← 현금 이동 없음
② 리스료 지급 (현금)
   (차) 리스부채        80     (대) 현금          100
       이자비용         20
③ 감가상각 (비현금)
   (차) 감가상각비     200     (대) 사용권자산     200
```

### C~D. 거래 성격
- **현금**: 리스료 지급만
- **비현금**: **리스 개시 시 자산·부채 동시 인식**(가장 중요), 감가상각, 리스부채 이자, 리스 조건 변경

### E. BS 증감 사용 가능성
**불가능** ❌

**WHY**: 리스 개시는 현금이 전혀 안 움직이는데 자산·부채가 동시에 크게 증가한다. BS 증감을 현금흐름으로 보면 **존재하지 않는 현금흐름을 만들어낸다**.

### F. Bridge
```
기초 리스부채
+ 신규 리스 인식액              ← 비현금 (주석 공시 대상)
+ 리스부채 이자비용             ← 비현금 (또는 이자지급으로 별도)
- 리스료 지급액 (현금)          ← 재무활동 유출
± 리스 조건 변경                ← 비현금
± 환율변동 (외화 리스)          ← 비현금

```

### G. 분류
**재무활동** — 리스부채의 상환

## 4-12. 원화가지급금 — Key-in의 대표 사례

### A. 계정의 경제적 실질
가지급금은 **거래의 내용이나 금액이 확정되지 않은 상태에서 임시로 처리하는 계정**이다. 은행에서는 결제 과정의 미결제 항목, 내부 이체 대기 항목 등이 여기 쌓인다.

### B~E. 왜 문제인가
가지급금은 성격상 **다양한 거래가 섞여 있다**. 어떤 것은 현금거래, 어떤 것은 단순 계정 대체다. BS 증감만으로는 이를 구분할 수 없다.

### H. 현재 정산표에서의 처리 `[파일 확인]`

정산자료 221행(원화가지급금):
```
AL221 = 150,198,747,436   ← Key-in (비현금거래 대변)
```

> **WHY Key-in이 필요한가**: 가지급금 잔액 변동 중 **비현금 대체분(1,502억)**을 수기로 분리하지 않으면, 이 금액이 통째로 영업활동 현금흐름으로 잡힌다. 즉 **실제로는 계정 간 대체에 불과한 1,502억이 현금 유출입으로 둔갑**한다. `[논리 추론]`

### I. 검토 시 주의사항
1. **가지급금 내역 분석 필수**: 잔액이 크면 반드시 구성 내역을 확인해야 한다.
2. **기말 미정리 잔액**: 결산 시점에 가지급금이 크게 남아 있으면 그 자체가 내부통제 이슈다.
3. **Key-in 근거자료 보관**: 1,502억을 왜 비현금으로 분류했는지 근거 조서가 필요하다. `[확인 필요]`

# 6. 비현금거래 조정

## 6-1. 비현금거래란 무엇이며 왜 중요한가

**정의** `[일반 원칙]`: 현금및현금성자산의 유입·유출을 수반하지 않는 투자·재무활동 거래.

**왜 중요한가**: 두 가지 이유가 있다.
1. **CF에서 제외해야 한다** — 현금이 안 움직였으므로 현금흐름표 본문에 넣으면 허위 현금흐름이 된다.
2. **주석으로 공시해야 한다** — K-IFRS 제1007호 문단 43. 재무제표 이용자가 기업의 투자·재무활동 전모를 파악하려면 비현금거래 정보가 필요하다.

## 6-2. 정산표에서 비현금거래를 처리하는 메커니즘 `[파일 확인]`

정산자료는 **AI(차변) / AL(대변)** 두 열로 비현금거래를 처리한다.

**부호 정의** (4행): AI = 현금감소, AL = 현금증가
**검증식에서의 부호**: `N = ... − AI + AL`

이 설계의 우아함은 **비현금거래가 자동으로 상쇄**된다는 점이다. 한 거래를 AI와 AL에 짝으로 기록하면, 검증식에서 `−AI + AL = 0`이 되어 현금흐름에 영향을 주지 않는다.

**대표 사례: 공정가치위험회피 파생 환산차대 (190행)** `[파일 확인]`
```
AI190 = 15,658,562   (해외사업환산차대 유입)
U190  = 15,658,562   (자산부채증감으로 이관)
N190  = ... + U190 − AI190 = +15,658,562 − 15,658,562 = 0 ✅
```

> **학습 포인트**: 비현금거래는 "들어왔다가 나가는" 형태로 기록되어 순효과가 0이 된다. 이것이 정산표가 비현금거래를 다루는 표준 패턴이다.

## 7-3. 요청하신 특정 항목 상세 분석

### ① 원화가지급금 비현금대차 (AL221 = 150,198,747,436) `[파일 확인]`

**왜 이 숫자를 입력하지 않으면 CF가 틀어지는가:**

가지급금은 잔액만 보면 그 안에 무엇이 섞여 있는지 알 수 없다. 예를 들어:
```
가지급금 기초  82 → 기말 1,584 (증감 +1,502억)

이 증가의 실제 내용이:
  Case A: 실제 자금 지출 1,502억  → 영업활동 현금유출 1,502억 ✅
  Case B: 단순 계정 대체 1,502억  → 현금흐름 0 ✅

BS 증감만으로는 A와 B를 구분할 수 없다.

# 8. 환율변동효과

## 8-1. 왜 별도 표시하는가 `[일반 원칙]`

K-IFRS 제1007호 문단 28:
> 외화로 표시된 현금및현금성자산의 환율변동효과는 **영업·투자·재무활동 현금흐름과 구분하여 별도로 표시**한다.

**WHY**: 환율이 변해서 외화현금의 원화 환산액이 커진 것은 **현금이 들어온 것이 아니다**. 달러 100은 그대로 100인데 원화 표시만 커졌을 뿐이다. 이를 영업활동 등에 포함하면 실제로 벌지 않은 현금을 벌었다고 표시하게 된다.

**동시에 무시할 수도 없다**: 기초현금 + 3대 활동 = 기말현금이 성립하지 않기 때문이다. 그 차이가 바로 환율효과다. 그래서 **별도 라인으로 표시하되 순증감 계산(I+II+III)에서는 제외**하는 독특한 구조를 갖는다.

## 8-2. 파일에서의 환율효과 산출 `[파일 확인]`

             = −정산자료!P8 + 정산자료!S8 + 정산자료!AI8

```

| 정산자료 S8 | 436,994,207,084.84 | 현금성자산 관련 비현금수익 |

## 8-3. 환율효과와 환산차대의 구분 — 가장 헷갈리는 지점

두 개념이 자주 혼동된다. 명확히 구분하자. `[일반 원칙]`

| 구분 | 외화환산손익 | 해외사업환산차대 |

# 10. 계정별 Roll-forward 공식

> 원장만 보고 CF를 재구성할 때 사용할 **공식 모음**이다.

## 10-1. 자산 계정 일반형

```
기초 장부금액
+ 현금 취득액                          ← CF 유출 (투자활동 Z / 영업활동 U)
- 현금 처분액(장부금액 기준)           ← CF 유입 (투자활동 W / 영업활동 U)
± 공정가치 평가손익                    ← 비현금 (P/S)
+ 상각액 (현할차·프리미엄)             ← 비현금 (P/S)
- 감가상각비 / 손상차손                ← 비현금 (P)
± 환율변동효과                         ← 비현금
± 계정 대체                            ← 비현금 (AI/AL)
= 기말 장부금액
```

## 10-2. 부채 계정 일반형

```
기초 장부금액
+ 현금 조달액                          ← CF 유입 (재무활동 AC / 영업활동 U)
- 현금 상환액                          ← CF 유출 (재무활동 AF / 영업활동 U)
+ 할인발행차금 상각                    ← 비현금 (P)
± 공정가치 평가손익                    ← 비현금 (P/S)
+ 비현금 인식 (신규 리스 등)           ← 비현금 (AL)
± 환율변동효과                         ← 비현금
= 기말 장부금액
```

## 10-3. 계정별 구체 공식

```

± 정상↔부실 계정대체                   ← 비현금

```

## 11-2. Step 1 — 정산표 작성

각 계정의 증감을 원인별로 분해한다.

### 대출채권 (기초 824 → 기말 948)
```
Roll-forward:
  기초                          824
  + 신규 실행                  +500  (현금유출)
  − 원금 회수                  −300  (현금유입)
  − 대손 제각                   −50  (비현금)
  = 기말                        948  ✅

정산표:
  M (증감)         = +150
  P (대손상각비)   = +50    ← 비현금비용 가산
  U (영업CF)       = −200   ← 실제 현금흐름 (−500 + 300)
  검증 N = M + P + U = 150 + 50 + (−200) = 0 ✅
```

> **핵심**: BS 증감 +150 ≠ 실제 현금흐름 −200. 차이 50이 대손 제각(비현금).

### FVOCI (기초 659 → 기말 676)
```
Roll-forward:
  기초                          800
  + 취득                       +200  (현금유출)
  − 처분(장부금액)             −190  (현금유입)
  + OCI 평가이익                +10  (비현금, 당기순이익 아님)
  = 기말                        820  ✅

정산표:
  M (증감)         = +20
  W (처분)         = 200    ← 투자활동 유입 (현금 수령액)
  Z (취득)         = 200    ← 투자활동 유출
  S (처분이익)     = 10     ← 비현금수익 차감 (당기손익에 있음)
  AI (OCI평가)     = 10     ← 비현금 (당기순이익에 없음)
  검증 N = 20 + 0 − 10 + 0 + 200 − 200 − 10 + 0 = 0 ✅
```

> **핵심**: BS 증감 +20인데 총액은 취득 200 / 처분 200. 순증감으로는 330억 규모 거래가 완전히 은폐된다.

### 유형자산 (기초 247 → 기말 231)

  − 감가상각비                  −30  (비현금)

```

### 리스 (사용권자산 100→130, 리스부채 100→135)
```

  기초  82 + 신규인식 60 − 상각 30 = 130 ✅
리스부채 Roll-forward:
  기초  82 + 신규인식 60 + 이자 5 − 지급 30 = 135 ✅

# 15. 핵심 요약

## 15-1. 한 문장 요약

> **현금흐름표 작성이란, 모든 BS 계정의 잔액 변화를 ①현금거래 ②비현금손익 ③비현금대체로 남김없이 분해하여, 그 결과 계산된 기말현금이 원장과 일치함을 증명하는 작업이다.**

## 15-2. 반드시 기억할 10가지

| # | 원칙 |
|---|---|
| 1 | **BS 증감 ≠ 현금흐름.** 부호까지 반대인 경우가 실제로 존재한다 (대출채권: +7.8조 vs −6.3조) |
| 2 | **최종 검증은 기말현금 = 원장.** 이것이 맞으면 큰 틀에서 검증된 것이고, 틀리면 반드시 원인을 찾아야 한다 |
| 3 | **간접법은 당기순이익에서 출발한다.** 당기순이익에 없는 항목(OCI)은 조정 대상이 아니다 |
| 4 | **은행은 영업활동 범위가 넓다.** 대출·예금·트레이딩은 본업이므로 영업활동 |
| 5 | **투자·재무활동은 총액표시.** 순증감으로는 실제 거래 규모가 은폐된다 (FVOCI: 순증감 −2,922억 vs 총액 21조) |
| 6 | **BS만으로 알 수 없는 정보는 M시트/Key-in으로.** 총액, 비현금 대체가 대표적 |
| 7 | **비현금거래는 AI/AL 짝으로 기록하여 상쇄.** 순효과 0이 되도록 설계 |
| 8 | **환율효과는 현금흐름이 아니다.** 별도 표시하되 순증감 계산에서 제외 |
| 9 | **단수조정 셀은 필수 장치다.** 함부로 삭제하면 정합성이 깨진다 |
| 10 | **검증은 계정별(N열) → 소계별 → 최종(기말현금) 3층으로.** 오류를 계정 단위로 특정할 수 있다 |

## 15-3. 정산표 없이 원장만으로 CF를 재구성하는 절차

```
1. BS 전 계정을 세로로 나열, 기초·기말·증감 산출

2. 각 계정마다 질문한다:
   "이 잔액 변화의 원인은 무엇인가?"
   → 현금거래 / 비현금손익 / 비현금대체로 분해

3. 총액표시가 필요한 계정(투자·재무)은 원장 상세를 조사
   → 취득/처분, 증가/감소 총액 파악

4. 비현금손익을 PL에서 골라내 손익조정에 반영
   → 단, OCI 항목은 제외 (당기순이익에 없음)

5. 비현금대체를 식별하여 상쇄 처리 + 주석 공시

6. 계정별 검증: 증감 = 원인의 합

7. 활동별 집계

8. 최종 검증: 기초현금 + 3활동 + 환율효과 = 기말현금(원장)
   → 불일치 시 2~7 반복
```

## 15-4. 가장 흔한 오류 Top 5
