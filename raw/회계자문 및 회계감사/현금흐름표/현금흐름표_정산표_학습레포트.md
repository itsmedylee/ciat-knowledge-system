## 1. 파일 아키텍처 — 4계층 설계

실무에서 가장 먼저 배울 것은 수식이 아니라 **데이터 흐름의 층위**다.

```
[1층] 원천 TB (매트릭스)
      정산표2025.03  / 정산표2024.12
      A열 연결계정코드 · B열 계정명 · C열 Lvl(1~6) · D열~AN열 = 법인별 잔액
      (지주, 은행A, 은행B, 투자증권, 캐피탈, 저축은행, 신용정보,
       시스템, 자산운용, 벤처투자, 구조화기업 33개, 998:연결조정)
                    │  VLOOKUP(계정코드, 정산표, 법인열번호, FALSE)
                    ▼
[2층] 법인별 CF정산표 (동일 템플릿 10개 + 펀드)
      지주 / 은행A / 은행B / 캐피탈 / 투자증권 / 저축은행 /
      자산운용 / 벤처투자 / 시스템 / 신용정보
      펀드CF(33개 펀드 세로 나열, 1,589행) → 펀드합계(SUMIF/SUMIFS 집계)
                    │  =은행A!W17 형태로 셀 단위 참조
                    ▼
[3층] 연결현금흐름정산표_2025.03  (493행 × AM열)
      + 상세분석(별도합산 vs 연결 차이 원인)
                    │  =연결현금흐름정산표_2025.03!E418
                    ▼
[4층] CF공시용  (제15기/제14기 2기 비교표 + 수정전/수정후 대사)
```

### 1.1 설계에서 배울 점 5가지

| 기법 | 파일 내 구현 | 왜 중요한가 |
|---|---|---|
| **열번호의 셀 파라미터화** | `B1=70`, `C1=73` 두 셀에 VLOOKUP 열번호 저장 → 전 시트가 `VLOOKUP(...,$A:$BU,C1,FALSE)` 로 참조 | 원천 TB에 법인 1개 추가되면 셀 2개만 수정. 하드코딩 시 수천 개 수식 수정 |
| **열번호 자동산출(진화형)** | `상세분석!F15 = INDEX($F$4:$XFD$4, MATCH(F16,$F$5:$XFD$5,))` | 법인명(헤더 문자열)으로 열번호를 역산 → 열 순서가 바뀌어도 무너지지 않음 |
| **전기 TB 병존** | `정산표2024.12` 시트를 같은 파일에 유지 | 기초잔액을 손으로 옮기지 않음 = 기초잔액 오류 원천 차단 |
| **템플릿 동일화** | 자회사 10개 시트가 **행번호까지 동일**(단, 일부 오프셋 존재) | 연결시트에서 `=은행A!W36` 같은 직접 참조가 가능 |
| **버전·기준일 파일명** | `v1_0_0507`, `v1_4_대손준비금수정`, `_2503` | 결산 리뷰 이력 추적. 감사대응 시 필수 |

> ⚠️ **관측된 위험**: 자회사 시트 간 행 오프셋이 일정하지 않다. 예) 연결시트 17행 ↔ `지주!Y26`, 연결시트 134행 ↔ `지주!W130`, 연결시트 166행 ↔ `은행A!AE159`. **템플릿 동일화의 이점이 이미 일부 훼손된 상태**이며, 신규 계정 추가 시 참조 어긋남이 발생할 수 있다.

## 2. 정산표(Work Sheet) 열 구조 — 현금흐름표의 본질

이 파일의 핵심은 493행짜리 `연결현금흐름정산표`다. 열 구조를 이해하면 CF 작성 원리 자체를 이해하게 된다.

| 열 | 헤더 | 내용 | 부호 규칙 |
|---|---|---|---|
| B | 연결COA | 계정코드 (VLOOKUP 키) | — |
| C | 계정과목 | 표시명 | — |
| D | 제14기 (2024-12-31) | 기초잔액 | **자산 (+) / 부채·자본 `-VLOOKUP` 으로 부호반전** |
| E | 제15기 (2025-03-31) | 기말잔액 | 동일 |
| F | 증감 | `=E-D` | — |
| G | 활동구분 | 영업 / 투자 / 재무 / N/A | 분류 의사결정의 기록 |
| **H** | **검증** | `=SUM(I:AG)+F-SUM(K)-SUM(N)` **= 0** | 핵심 |
| I | 당기순이익 | 최상단 1행에만 | — |
| J / K | 비용 계정명 / COA | 라벨 + 코드 | K는 SUM에서 제외해야 함 |
| **L** | 비용가산 | `=IFERROR(VLOOKUP(K,TB,열,FALSE),0)` | (+) |
| M / N | 수익 계정명 / COA | 라벨 + 코드 | N은 SUM에서 제외 |
| **O** | 수익차감 | `=-IFERROR(VLOOKUP(N,TB,열,FALSE),0)` | **(-) 부호반전** |
| **P** | 자산·부채의 증감 | **잔여(plug)** | 후술 |
| Q | 구분 | 이자/배당 귀속 법인 라벨 | — |
| R / S | 이자수취 / 이자지급 | 현금기준 | (+) / (-) |
| T / U | 배당금수취 / 법인세납부 | 현금기준 | (+) / (-) |
| V·W / X·Y | 투자유입(라벨/금액) / 투자유출 | 총액표시 | (+) / (-) |
| Z·AA / AB·AC | 재무유입 / 재무유출 | 총액표시 | (+) / (-) |
| AD·AE / AF·AG | **비현금 유입 / 비현금 유출** | 라벨 + 금액 | 합계 = 0 |

### 2.1 지배 항등식 (이걸 외우면 끝)

```
ΔBS(F) = -[ 손익조정(L+O) + 운전자본증감(P)
           + 이자수취(R) + 이자지급(S) + 배당수취(T) + 법인세납부(U)
           + 투자유입(W) + 투자유출(Y)
           + 재무유입(AA) + 재무유출(AC)
           + 비현금(AE+AG) ]
```

파일에서는 이를 `H열 = SUM(I:AG) + F = 0` 으로 구현한다.

> **왜 `+F` 인가**: 자산 증가(F>0)는 현금 유출(-)이므로, 배분열의 합이 `-F`가 되어야 한다. 따라서 `합 + F = 0`.

### 2.2 K열·N열 트릭 — 초보자가 가장 많이 틀리는 곳

```
H17 = SUM(I17:AG37) + F17 - SUM(K17:K36) - SUM(N17:N36)
                            ^^^^^^^^^^^^^^^^^^^^^^^^^^^^
```
K열·N열에는 **계정코드(예: 5031010103)라는 숫자**가 들어 있다. I~AG 구간을 통째로 SUM하면 이 코드값이 금액에 섞여 들어간다. 그래서 다시 빼준다.

> 💡 **더 나은 설계**: 코드열을 텍스트 형식으로 저장하거나, 배분 영역 밖(예: AO열 이후)으로 물리적 분리. 현재 구조는 **행을 추가하면 `-SUM(K17:K36)`의 범위가 자동 확장되지 않아** 검증이 소리 없이 깨질 수 있다. (실제로 H17 = **-0.43**, H59 = **+0.43**, H9 = **0.25** 로 잔차 존재)

### 2.3 P열 = 잔여(plug)의 양면성

```
P17 = ROUND( -F17 - SUM(L,O,R,S,T,U,W,Y,AA,AC,AE,AG 범위), )
```

**장점**: 운전자본 증감을 별도 집계할 필요 없음. 검증열이 자동으로 0.
**치명적 함정**: 분류 누락·오류가 전부 **운전자본 증감 속으로 흡수되어 검증에 걸리지 않는다.**

| 누락 사례 | P열이 흡수한 결과 | 재무제표 왜곡 |
|---|---|---|
| 미지급금 계상 유형자산 취득을 비현금 처리 안 함 | 기타자산 증감 과대 | 투자활동 유출 과대계상 |
| 유효이자 상각액을 AE/AG에 안 넣음 | 대출채권 증감 왜곡 | 영업활동 왜곡 |
| 리스개시 시 사용권자산/리스부채 인식 누락 | 기타자산·기타부채 증감 | 투자·재무 활동 왜곡 |

→ **실무 대응**: P열이 plug인 계정은 반드시 **별도 명세(주석용 증감표)와 크로스체크**할 것. 파일에서는 `상세분석` 시트와 `건설중인자산(유형)_2503`, `감가상각비명세_2503`(4,374행), `리스부채만기구조_2503`가 그 역할을 한다.

## 3. 현금및현금성자산의 정의 — 첫 단추

```
E9 (기말 현금및현금성자산)
 = VLOOKUP(1100000000, TB, 열)   ← "현금및예치금" 총액
   - E15                          ← 3개월 초과 예치금
   - E10                          ← (추가 차감 항목)
```

- **K-IFRS 1007.6~9**: 현금성자산은 *취득일로부터 만기 3개월 이내*, 확정금액 현금 전환이 용이하고 가치변동 위험이 경미한 투자자산.
- 금융업 BS의 "현금및예치금"에는 3개월 초과 예치금이 섞여 있으므로 **반드시 분리**해야 한다.
- 분리된 3개월초과예치금(E15)은 `P15 = -F15-L15-L14-O15-O14` 로 **영업활동 자산 증감**에 배치 → CF공시용 B29 "예치금의 증감".

> ⚠️ **해석상 다툼 가능**: 금융회사의 한국은행 지급준비예치금·사용제한 예치금을 현금성자산에 포함할지는 회사별 정책 차이가 있다. 주석에 사용제한 예금을 별도 공시하는 것이 일반적(1007.48). **회사 정책 확인 필요**.

## 4. 금융업 CF의 핵심 — 이자·배당·법인세 gross-up

### 4.1 구조

```
1. 당기순이익                        E416 = I9 (TB의 당기순이익 계정)
2. 조정사항                          E417 = SUM(E418:E436)
   └ 이자수익  E418 = -PL 이자수익 전액   (1,371,380백만 차감)
   └ 이자비용  E419 = +PL 이자비용 전액   (  765,221백만 가산)
   └ 법인세비용 E436 = +PL 법인세 전액
3. 영업활동 자산부채의 변동          E437 = SUM(E438:E450)
──────────────── 여기까지 = "영업에서 창출된 현금흐름" ────────────────
```

### 4.2 왜 이렇게 하는가 (기준 근거)

| 기준 | 내용 |
|---|---|
| K-IFRS 1007.31 | 이자·배당의 수취·지급은 **각각 별도 공시** |
| K-IFRS 1007.33 | 금융회사의 이자수취·지급·배당수취는 통상 **영업활동**으로 분류 |
| K-IFRS 1007.35 | 법인세로 인한 현금흐름은 별도 공시, 원칙적으로 영업활동 |
| K-IFRS 1007.21 | 총액표시 원칙 (예외 1007.22~24: 금융회사 회전율 높은 항목은 순액 가능) |

**개념적 요체**: 발생주의 이자수익(PL)을 **전액 제거**한 뒤 → 현금기준 이자수취를 **다시 넣는다**. 그 차액이 미수이자 증감이다. 이자수취를 별도 라인으로 뽑지 않는다면 미수수익 증감을 운전자본에 넣어야 하는데, 금융지주는 금액이 커서 정보가치가 떨어진다.

### 4.3 실무 팁 — 이자 현금흐름의 산출

파일은 R/S/T/U 열을 **자회사 시트에서 직접 받아온다** (`R71 = 지주!R70`, `R72 = 은행A!R70`). 즉, **연결 레벨에서 역산하지 않고 자회사가 산출한 현금이자를 집계**한다.

이유: 미수이자·미지급이자의 상각, 부실여신 이자 미인식, 이자와 원금의 혼합회수 등으로 **역산이 부정확**하기 때문. → **자회사 자료요청서(PBC)에 "현금기준 이자수취/지급"을 명시적으로 포함**해야 한다. (파일에 `PBC>>` 구분시트가 존재하는 이유)

## 7. 연결 특유 논점

### 7.1 별도합산 ≠ 연결 — `998:연결조정` 트랙

`상세분석` 시트는 "**계정별 별도-연결 차이원인 분석**"이라는 제목 아래, 계정별로 다음 대사표를 만든다.

| 지주 | 은행A | 은행B | 투자증권 | … | 펀드합계 | **별도합산(R)** | **연결(CF정산표)(S)** | **차이(T)** | **원인(U)** | 검증(V) |

```
R30 = SUM(G30:Q30)                      별도합산
S30 = SUM(연결현금흐름정산표!W38:Y50)     연결 CF 금액
T30 = S30 - R30 - F30                    차이 (F=998:연결조정)
V30 = (U30 = T30)  → TRUE                원인이 차이를 100% 설명하는지
```

> 💡 **이 구조가 학습 포인트다.** 차이를 "있다/없다"로 끝내지 않고 **"원인(U열)에 입력한 설명금액이 차이(T열)와 일치하는지"를 다시 TRUE/FALSE로 검증**한다. 미설명 차이를 0으로 만드는 강제장치.

실제 결론 메모(`상세분석!C35`):
> "원화매도가능금융자산매매익(계정코드 4041010102)과 관련된 998:연결조정분개 때문임" — 분개까지 명시(차변 원화기타포괄손익인식증권평가이익 / 대체이익잉여금 → 대변 매매익)

### 7.2 구조화기업(펀드) 33개의 확장가능 설계

```
펀드CF (1,589행)  : 펀드별 CF정산표를 48행 블록으로 세로 반복
                    목차 셀에 =A7, =A55, =A103 … 하이퍼링크식 인덱스
       │  SUMIF / SUMIFS 로 집계
       ▼
펀드합계 (386행)  : 연결정산표와 동일 템플릿
       │  =SUM(펀드합계!W46:W80)
       ▼
연결현금흐름정산표 : 1개 열로 참여
```

집계식 예:
```
펀드합계!R11 = SUMIFS(펀드CF!R:R, 펀드CF!C:C, 펀드합계!C11, 펀드CF!Q:Q, Q11)
```
→ **계정과목 + 구분(Q) 2개 키로 매칭**. 셀 직접참조가 아니라 SUMIFS 기반이므로 **펀드가 늘어나도 블록만 추가하면 됨**(단, 검증합계식 `=H12+H58+H106+…`은 수동 확장 필요 — 개선 여지).

> ⚠️ **관측된 리스크**: `펀드CF!H8`의 검증 합계는 34개 항을 손으로 나열한 수식이다. 펀드 신규 편입 시 **이 수식 갱신 누락 = 검증 무력화**. 실무에서는 `SUMIF(펀드CF!C:C,"검증용",…)` 또는 헬퍼열 방식으로 바꿀 것을 권장.

## 8. 외화 환율변동효과 — 가장 정교한 부분

### 8.1 파일의 구현

```
E424 (조정사항 '외화환산손익') = P455 - P454
                                = 외화환산손실 - 외화환산이익 = -4,180,028,087

H424 = (계정별 L/O 열 외화환산 항목 100여 개의 총합) = +4,579,310,869
H425 = H424 - E424 =  8,759,338,956
H426 = (H425 = I417) → TRUE            ← 논리검증
I417 = H417 - E417 =  8,759,338,956    ← 조정사항 총액 차이

F491 (환율변동효과) = -J424 + H424 - H491 =  8,759,338,956.77
```

### 8.2 개념 해설

1. **PL의 외화환산손익**(계정 4081010102 / 5081010102)은 조정사항으로 제거한다.
2. 그러나 **BS 계정별로 배분한 외화환산 조정액의 총합(H424)** 과 **PL 총액(E424)** 은 다르다.
3. 그 차이가 곧 **현금및현금성자산 자체의 환율변동효과**다.
4. K-IFRS **1007.28**: 외화표시 현금및현금성자산의 환율변동효과는 **영업·투자·재무와 구분하여 별도 표시**하되, 조정 목적으로 현금흐름표에 표시한다.

> 💡 **학습 포인트**: 환율변동효과를 "그냥 차액"으로 밀어 넣는 파일이 많다. 이 파일은 `H426 = (H425 = I417) → TRUE` 라는 **논리 등식으로 그 차액이 설명 가능함을 증명**한다. 자작성 시 반드시 모방할 기법.
> ⚠️ 단, `H491 = -0.75` 라는 **수동 조정 상수**가 박혀 있다. 단수차이 조정용으로 보이나, **하드코딩된 plug는 반드시 코멘트로 근거를 남겨야** 한다.

### 9.2 PL Tie-out — 차이를 "설명"하는 문화

`연결현금흐름정산표` J~L열은 조정사항 항목별로 **PL 금액과 대조**하고, 0이 아닌 차이에 **사유 메모**를 붙인다.

| 항목 | 정산표(E) | PL(J) | 차이(K) | 사유 메모 (L열) |
|---|---|---|---|---|
| 이자수익 | -1,371,380,243,523 | 동일 | **0** | — |
| 당기손익-공정가치 금융자산 순손익 | -58,193,507,122 | -64,408,231,951 | 6,214,724,829 | "평가손익 및 투자활동 관련 처분손익만 조정하므로 차이발생" |
| 신용손실충당금전입액 | 224,291,811,942 | 215,903,067,184 | 8,388,744,758 | "대출채권매각손익, 상환손익" → 다시 `N423 = P457+P458-P459` 로 7,515백만 설명 |
| 퇴직급여 | 10,844,671,018 | 14,419,341,229 | -3,574,670,212 | "자산운용은 100% 확정기여형, 은행B·투증에도 DC형 일부. 시스템은 매출원가에 퇴직급여 포함" |

> 💡 **이것이 이 파일에서 배울 최고의 습관**: 차이를 0으로 만들려 억지 조정하지 않고, **왜 다른지를 셀 옆에 문장으로 남긴다.** 감사인·심사역이 가장 먼저 보는 부분이며, 다음 분기 담당자가 바뀌어도 논리가 승계된다.

### 9.3 별도 파일의 "계정과목명 문자열 대사"

`별도 검증파일 CF` 시트의 O·P열:
```
O7 = "I. 영업활동으로 인한 현금흐름"   (전기 공시 보고서에서 복사한 계정명)
P7 = (O7 = B7) → TRUE
```
→ **금액이 아니라 계정과목 문자열 자체를 전기 보고서와 1:1 대사**한다.
- 목적: 계정명 오탈자, 항목 순서 변경, 신규 항목 누락 방지.
- 메모(`N35`): "**신규계정과목 발생여부 확인 필요(인터뷰, 합계오류 등으로 파악)**"

> 이 기법은 DART 공시 XBRL 태깅 오류 방지에도 직결된다. **자작성 시 반드시 도입 권장.**

### 9.4 수정전/수정후 비교 열 (CF공시용 J~M열)

```
J열 = 수정전 금액 (직전 버전)
L열 = C - J   (항목별 차이)
M열 = D - K   (소계 차이)
```
→ **버전 간 변동을 파일 안에서 즉시 확인**. 리뷰 코멘트 반영 누락 방지.

## 10. 대손준비금 — 금융업 특유 논점 (파일명 `v1_4_대손준비금수정`)

### 10.1 개념

- **근거**: 금융지주회사감독규정 (은행: 은행업감독규정) — *조문 번호는 최신 개정 확인 필요*
- **내용**: K-IFRS상 손실충당금이 **감독목적 요구 충당금**에 미달하면, 그 차액을 **대손준비금**으로 적립.
- **성격**: **이익잉여금 내 적립금**. 비용이 아니다.

파일 주석20 원문(요지):
> "회사는 금융지주회사감독규정 등에 근거하여 기업회계기준에 의한 손실충당금이 감독목적상 요구되는 충당금 적립액 합계에 미달하는 금액만큼을 대손준비금으로 적립하도록 요구받고 있습니다."
> "대손준비금 반영 후 조정손익 및 기본주당손익은 **기업회계기준에 의한 수치가 아니며**, 전입·환입액을 당기순이익에 반영하였을 경우를 가정하여 산출"

### 10.2 현금흐름표에 미치는 영향

| 항목 | 영향 |
|---|---|
| 현금흐름표 | **영향 없음** — 자본 내 계정 대체(이익잉여금 → 대손준비금)이므로 현금·손익 모두 불변 |
| 자본변동표 | **영향 있음** — 별도 라인 표시 |
| 주석 | 대손준비금 잔액, 전입(환입)예정액, 반영 후 조정손익·주당손익 공시 |
| 이익잉여금처분계산서 | 적립·이입 표시 |

> ✅ **정리**: 대손준비금은 CF 작성자가 **"건드리지 않아야 맞는"** 항목이다. 다만 **잔액 대사(주석20 ↔ 정산표 ↔ 연결결산파일 부호 반대)** 는 필요. 파일 `주석20!Q77`에 "**<연결대손준비금>_연결결산파일(부호 반대)**" 메모가 그 증거.
> ⚠️ 파일명이 `대손준비금수정`인 것으로 보아 v1_3 → v1_4에서 **잔액 또는 전입예정액 수정**이 있었던 것으로 추정되나, **구체 수정내역은 파일 내에서 확인되지 않음 — 확인 필요**.

## 14. 고객·비전문가 설명용 쉬운 표현

> **현금흐름표란?**
> 손익계산서는 "장부상 얼마 벌었나"를 보여주고, 현금흐름표는 "**통장에 실제로 얼마 들어왔나**"를 보여줍니다. 이 둘이 다른 이유는 외상매출, 감가상각비처럼 **돈이 오가지 않는 회계처리**가 있기 때문입니다.

> **정산표(Work Sheet)란?**
> 재무상태표의 **모든 계정을 한 줄씩 세워놓고, "이 계정이 작년 대비 늘어난 만큼의 돈이 어디로 갔는지"를 옆 칸에 하나씩 배분**하는 커다란 표입니다. 마지막에 배분한 금액의 합이 증감액과 딱 맞아떨어지면 완성입니다. 퍼즐 조각을 다 맞추면 그림이 완성되는 것과 같습니다.

> **비현금거래란?**
> 건물을 샀는데 **아직 대금을 안 냈다면**, 자산은 늘었지만 통장에서 나간 돈은 0원입니다. 이걸 "투자로 433억 썼다"고 쓰면 거짓말이 됩니다. 그래서 따로 빼두고 **주석에만 적습니다.**

> **은행 현금흐름표가 특히 어려운 이유**
> 일반 기업은 이자가 부수적이지만, 은행은 **이자가 본업**입니다. 그래서 장부상 이자(발생주의)를 전부 지우고, 실제로 받은 이자·낸 이자를 **다시 현금 기준으로 써넣는** 과정이 추가됩니다.

> **대손준비금은요?**
> 회계기준상 쌓아야 할 충당금보다 **금융감독원이 요구하는 금액이 더 많을 때**, 그 차액만큼 이익잉여금 안에 따로 표시해 두는 것입니다. **비용이 아니고 돈이 나가지도 않으므로 현금흐름표에는 나타나지 않습니다.**

## 15. 블로그 콘텐츠 제안

### 제목 후보
1. **「현금흐름표는 왜 항상 마지막에 안 맞을까 — 정산표 한 장으로 끝내는 법」**
2. 「간접법 현금흐름표, 실무자가 매번 틀리는 7가지 지점」
3. 「금융회사 현금흐름표가 유독 어려운 이유 — 이자를 두 번 쓰는 구조」
4. 「'검증란이 0이 나왔다'는 말을 믿으면 안 되는 이유」

### 도입부 (예시)
> 결산 마감 이틀 전, 현금흐름표의 마지막 줄이 3원 차이가 난다. 밤 11시에 셀을 하나씩 짚어가며 원인을 찾는다. 대부분의 실무자가 겪어본 장면이다.
> 문제는 3원이 아니다. **3원이 났다는 건 어딘가에서 2억이 두 번 상계되었을 수도 있다는 뜻**이기 때문이다.

### 본문 구조
| 절 | 내용 |
|---|---|
| 1 | 현금흐름표를 "손익계산서 고치기"로 배운 것이 첫 단추 오류 |
| 2 | 정산표의 지배 항등식 — ΔBS = 영업 + 투자 + 재무 + 비현금 |
| 3 | **실수 지점 ①** 운전자본을 plug로 두면 오류가 숨는다 |
| 4 | **실수 지점 ②** 비현금거래 12유형 — 미지급금 계상 취득, 리스 개시, 재분류 |
| 5 | **실수 지점 ③** 계정 하나에 성격이 두 개 (수익증권 배당금 사례) |
| 6 | **실수 지점 ④** 환율변동효과를 차액으로만 밀어 넣기 |
| 7 | 실제 금융지주 파일의 7단계 검증 구조 |
| 8 | **의사결정 관점** — 경영진이 CF에서 봐야 할 것: 영업에서 창출된 현금 vs 당기순이익의 괴리 |

### 사례 (실화 각색)
- 무형자산 취득 433억 중 미지급금 계상분을 투자활동 유출로 처리 → 투자활동 현금흐름 433억 과대, 기타부채 증감 433억 과대 → **검증란은 0. 발견 불가.**
- 사용권자산 취득을 투자활동에 계상 → 투자유출·재무유입 동시 과대 → 총계는 맞음.

### 결론
> 현금흐름표의 품질은 **"맞았는가"가 아니라 "왜 맞았는지 설명할 수 있는가"** 로 판정된다. 검증란이 0인 파일과, 차이의 사유가 셀 옆에 문장으로 적힌 파일은 전혀 다른 물건이다.
