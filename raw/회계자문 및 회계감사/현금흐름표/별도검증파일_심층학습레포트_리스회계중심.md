# PART Ⅰ. "검증 파일"이라는 개념

## 1. 파일 구조 (3계층 + 뒷단)

```
[원천]  지주정산표_2503 (4,161행 × 3열: 계정코드 | 계정명 | 금액)
        지주정산표_2412_전기말 / _2403_전분기 / _2406 / _2306
        전기DART_기말 (1,826행) / 전기DART_변동 (1,098행)  ← 공시 확정본 텍스트
                    │
                    │  VLOOKUP(계정코드, 지주정산표_2503!A:C, 3, 0)
                    ▼
[본문]  BS · PL · CE · CF  (원 단위)
        BS_천 · PL_천 · CE_천 · CF_천  (천원 단위, ROUND(/10^3))
                    │
                    ▼
[주석]  1 ~ 29  (각 시트에 Backdata 블록 내장)
                    │
                    ▼
[뒷단]  건설중인자산(유형/무형)_2503 · 감가상각비명세_2503(4,374행)
        리스회계결산_2503 · 리스부채만기구조_2503(101열)
        사채 만기구조(기말)_2412 · 미지급비용명세(기말)_2412 등
```

### 1.1 설계 원칙 3가지

| 원칙 | 구현 | 효과 |
|---|---|---|
| **Single Source of Truth** | 모든 숫자가 `지주정산표_2503`에서 파생 | TB가 바뀌면 재무제표·주석이 동시에 갱신 |
| **원 단위 / 천원 단위 이중 트랙** | `BS` ↔ `BS_천`, `CF` ↔ `CF_천` | 계산은 원 단위, 공시는 천원 단위 |
| **공시 확정본 내장** | `전기DART_기말`, `전기DART_변동` 시트에 전기 공시본을 통째로 붙여넣음 | **전기 수치를 손으로 옮기지 않음** = 전기 비교표시 오류 차단 |

> 💡 **전기 DART 본문을 파일 안에 붙여두는 것**이 이 파일에서 가장 저비용·고효과 기법이다. `=C27=전기DART_기말!B973` 같은 셀 대 셀 비교가 가능해진다.

## 2. 검증 아키텍처 6종 — 이 파일의 본체

| 유형 | 예시 수식 | 판정 대상 |
|---|---|---|
| ① **합계 검증** | `BS_천!F16 = (D16 = SUM(D8:D15))` → TRUE | 소계 = 구성항목 합 |
| ② **BS/PL Ref** | `CF!L8 = (D8 = PL!E26)` → TRUE<br>`CF!L54 = (D54 = BS!E9)` → TRUE | 표 간 연결 (CF 당기순이익 ↔ PL, 기초현금 ↔ 전기 BS) |
| ③ **계정과목명 문자열 대사** | `CF!P7 = (O7 = B7)` → TRUE | **금액이 아니라 계정명 텍스트**를 전기 공시본과 1:1 비교 |
| ④ **주석 내 REF** | `주석11!H10 = (F10 = H62)` → TRUE | 주석 (1)구성내역표 ↔ (2)변동내역표 대사 |
| ⑤ **전기보고서 대사** | `주석11!C37 = (C27 = 전기DART_기말!B973)` | 전기 비교표시 금액 = 실제 공시 금액 |
| ⑥ **차이 병기** | `CF!I7 = D7-(D8+D9+D21+D28+D29+D27+D30)` | TRUE/FALSE와 **차이금액을 함께 표시** |

> **왜 ③번(문자열 대사)이 중요한가**
> 계정과목명이 바뀌면 DART XBRL 태깅이 깨지고, 전기 비교표시가 어긋난다. 금액 검증만으로는 절대 잡히지 않는다. `주석11!N35` 메모: *"신규계정과목 발생여부 확인 필요(인터뷰, 합계오류 등으로 파악)"* — **작성자가 이 위험을 명시적으로 인식하고 있다.**

## 3. 단수조정(천원 환산) 기법 — 실무 표준

천원 단위 환산 시 개별 항목을 각각 반올림하면 **소계가 안 맞는다**. 파일의 해법:

```
BS_천!D11 = ROUND(BS!D12/10^3,) **-1**      대출채권 및 수취채권
BS_천!D15 = ROUND(BS!D16/10^3,) **-1**      기타자산
BS_천!D20 = ROUND(BS!D21/10^3,) **+1**      당기법인세부채
BS_천!D22 = ROUND(BS!D23/10^3,) **+1**      기타부채
BS_천!D27 = ROUND(BS!D28/10^3,) **-1**      기타불입자본
BS_천!D29 = ROUND(BS!E30/10^3,) **-1**      이익잉여금(전기)
BS_천!D30 = ROUND(BS!D31/10^3,) **-1**      자본총계

→ F16/F23/F30/F31 합계검증 전부 TRUE, D33 = (자산총계 = 부채+자본) → TRUE
```

CF도 동일: `CF_천!D7 = ROUND(CF!D7/10^3,)-1`, `PL_천`, 주석11 `F12 = ROUND(R8/1000,0)-1`.

### 3.1 실무 원칙

| 원칙 | 내용 |
|---|---|
| **어디에 밀어 넣을 것인가** | **금액이 큰 항목**에 ±1을 흡수시킨다 (상대오차 최소화). 파일도 대출채권·기타부채·자본총계 등 큰 항목 선택 |
| **몇 개까지 허용되는가** | 항목 수 n개면 최대 ±n/2 원 수준. 그 이상이면 **원 단위 원본이 틀렸을 가능성** |
| **반드시 남길 것** | 합계검증 셀(F/G열)을 **조정 후에도 TRUE로 유지**. 조정하고 검증을 지우면 통제 붕괴 |
| ⚠️ **주의** | `-1`은 **하드코딩**이다. 다음 분기에 그대로 두면 오히려 틀린다. **매 분기 재산정 필요** |

> **CF의 이중 단수조정**: `CF!D56` 메모 *">>리스부채의 상환 단수차이 조정"* — 원 단위 CF에서도 이미 단수조정이 있었고, `CF_천`에서 한 번 더 조정한다. **2단 조정은 추적이 어려우므로 근거 메모 필수.**

## 4. 주석 자동화 패턴 — Backdata 블록

주석 시트마다 오른쪽(P열 이후)에 `<정산표 검증>` 이라는 **Backdata 블록**이 숨어 있다.

```
[주석 11 유형자산 구조]

왼쪽 (B~H열) = 공시될 표                    오른쪽 (P~S열) = Backdata
┌──────────────────────────┐   ┌──────────────────────────────┐
│ 구분 │취득원가│상각누계│장부가│   │계정코드│계정명│당기│전기      │
│ 업무용건물 │1,856,586│-176,059│1,680,526│  │1505020101│업무용건물│=VLOOKUP(...)│
└──────────────────────────┘   └──────────────────────────────┘
        ▲                                      │
        └──────  ROUND(R14/1000,0)  ────────────┘
```

### 4.1 배울 기법 4가지

**① 취득원가 역산**
```
C11 (취득원가) = F11 - D11        ← 장부가액 - 감가상각누계액
```
TB에는 취득원가와 상각누계액이 각각 있으므로 굳이 역산할 필요가 없어 보이나, **표시 정합성(장부가 = 취득 - 누계 - 손상)을 구조적으로 강제**하는 효과가 있다. `G열` 합계검증이 항상 TRUE가 되는 이유.

**② 변동표를 명세에서 SUMIFS로 자동 산출**
```
당기 취득 = SUMIFS(감가상각비명세_2503!H:H,          ← 최초 취득가액
                   감가상각비명세_2503!B:B,"임차점포시설물",
                   감가상각비명세_2503!F:F,">=20250101")   ← 취득일 필터
              - AA56 (대체분)

당기 상각 = -SUMIFS(감가상각비명세_2503!V:V,          ← 당기상각비
                    감가상각비명세_2503!B:B,"임차점포시설물",
                    감가상각비명세_2503!G:G,"<>소계")   ← 소계행 제외
```
> 💡 **`"<>소계"` 조건**이 핵심. 명세서에 소계행이 섞여 있어도 이중계상되지 않는다. 자산명세에서 주석 변동표를 뽑을 때 항상 필요한 방어장치.

**③ 건설중인자산 대체의 부호 연동**
```
AA56 (임차점포시설물 대체) = -AA58
AA58 (건설중인자산 대체)   = -W58 (= -기초잔액 157,422,200)
```
→ 대체는 항상 **두 계정 간 제로섬**. 한쪽을 다른 쪽의 마이너스로 정의하면 **대체 합계가 구조적으로 0**이 된다. 유형자산 변동표에서 "대체" 열 합계가 안 맞는 사고를 원천 차단.

**④ 기초·기말은 TB에서, 중간 변동만 명세에서**
```
기초(W) = VLOOKUP(정산표_2412_전기말)
기말(AB) = VLOOKUP(정산표_2503)
취득·처분·상각·대체 = 명세 SUMIFS
```
→ 기초·기말이 TB로 고정되므로, **변동 합계가 안 맞으면 즉시 드러난다.** (plug로 채우지 않는 설계)

## 6. 계약대장 설계 — 배울 점

### 6.1 계약코드 체계 (`1. 부동산리스` C1·E1·F1 헤더)

```
        10        12       2201      001
        ↑         ↑         ↑         ↑
    용도구분   계약형태   계약시작년월  일련번호
  사무실 10   전세 10
  사택   20   월세 20
             혼합 12

예) 10122201001 = 사무실 / 혼합(보증금+월세) / 2022년 1월 개시 / 1번
    10102303001 = 사무실 / 전세 / 2023년 3월 개시 / 1번  (지역사무실)
    20122304001 = 사택   / 혼합 / 2023년 4월 개시 / 1번  (임원 공관)
```
> **왜 좋은가**: 코드만 보고 계약 성격이 파악되고, 정렬 시 개시일 순으로 자동 정렬된다. **계약 갱신 시 새 코드가 아니라 기존 코드 유지 + 비고에 "24.12갱신"** 표기 → 이력 추적.

### 6.2 계약대장 필수 컬럼 (파일 기준)

| 그룹 | 컬럼 |
|---|---|
| 식별 | 번호 · 점명 · 운용형태 · 주소 · **내부거래 여부** · 거래상대방 |

## 7. 사용권자산 4구성요소 분해 — 가장 중요한 개념

K-IFRS 1116.24: 사용권자산 = ① 리스부채 최초측정액 + ② 개시일 이전 지급 리스료(**선급리스료**) - 리스인센티브 + ③ **리스개설직접원가** + ④ **복구원가 추정치**

파일은 이 4요소를 **계정 단위로 분리**한다.

| 구성요소 | 사용권자산 계정 | 상각비 계정 | 상각액 컬럼 |
|---|---|---|---|
| ① 리스부채 분 | `1707010110 / 1508010101` 사용권자산(업무용부동산) | `5302001010 / 5101050101` 사용권자산상각(업무용부동산) | AF열 (a) |
| ② 선급리스료 분 (보증금) | `1707030110 / 1508030101` 사용권자산(임차보증금_선급리스료) | `5302001030 / 5101050403` 사용권자산상각(임차보증금_선급리스료) | AG열 (b) |
| ④ 복구충당부채 분 | `1707020110` 사용권자산(복구충당부채) | `5302001020` 사용권자산상각(복구충당부채) | AH열 (c) |
| (차량) | `1707040110 / 1508040101` 사용권자산(업무용동산_차량) | `5302001040 / 5101050404` 사용권자산상각(업무용동산_차량) | — |

계약대장 검증식:
```
AE (총 감가상각비) = AF (a) + AG (b) + AH (c)
AD (잔여기간 월수) → 정액법: 월상각액 = 상각대상 사용권자산 / 잔여기간

예) 전산센터 ○층
    Z6 상각대상 사용권자산 = 1,875,539,138
    AD6 잔여기간 60개월
    AE6 총 월상각비 31,258,986 = AF6 28,416,012 + AG6 696,484 + AH6 2,146,490
```

> 💡 **왜 분해하는가**
> 1. **복구충당부채 분**은 복구충당부채 재추정 시 사용권자산이 조정되므로 별도 추적 필요 (해석 IFRIC / 1116.24(d))
> 2. **선급리스료 분**은 보증금 회수 시 처리가 다름
> 3. 주석 공시 및 세무조정(리스 관련 유보) 시 구분이 요구될 수 있음 — **확인 필요**
>
> ⚠️ 반면 **BS 표시는 합산**된다 (주석11: 사용권자산 → 업무용부동산 / 차량운반구 2줄). **관리는 세분, 공시는 통합**이 원칙.

## 8. 임차보증금 현재가치평가 — 한국 실무의 핵심 논점

### 8.1 처리 구조

무이자 임차보증금은 **명목금액 ≠ 공정가치**다. 차액을 어떻게 볼 것인가?

```
[개시 시]
차) 임차보증금                    357,017,066   (명목)
    사용권자산(임차보증금_선급리스료)  41,789,050   ← Q열 "선급리스료 - 임차보증금"
  대) 현금                        357,017,066
      (임차보증금현재가치할인차금)     41,789,050   ← 1602080101 / 1302010101

[매월]
① 보증금 현할차 상각 (이자수익 인식)
   차) 현재가치할인차금(임차보증금_선급리스료) 55,840,922
     대) 현재가치할인차금_이자수익 (4015000100)  55,840,922

② 선급리스료분 사용권자산 상각
   차) 사용권자산상각(임차보증금_선급리스료) 57,691,728
     대) (감가상각누계액(사용권자산_임차보증금_선급리스료)) 57,691,728
```

### 8.2 개념 정리

| 항목 | 논리 |
|---|---|
| 보증금 명목 - 현재가치 | = 임대인에게 **무상으로 자금을 빌려준 대가** = 실질적 선급리스료 |
| 선급리스료 | 사용권자산에 가산 (1116.24(b)) → 리스기간에 걸쳐 **감가상각** |
| 현재가치할인차금 | 리스기간에 걸쳐 **이자수익**으로 환입 (유효이자율법) |
| 순효과 | 매기 이자수익(+) 과 감가상각비(-) 가 동시 발생. 초기에는 상각비 > 이자수익 |

> ⚠️ **해석상 다툼 가능**
> - 무이자 보증금의 현재가치평가 자체는 K-IFRS 1109 최초측정(공정가치) 원칙에서 도출되나, **할인율 선정**(리스의 내재이자율 vs 증분차입이자율 vs 시장이자율)은 회사 정책 영역이다.
> - **세무상 처리는 다르다.** 법인세법상 임차보증금 현재가치할인차금 및 그 상각액은 **손금·익금 불산입**(유보)이 일반적이며, 세무조정 대상이다. **국세청 해석 및 최신 예규 확인 필요.**

## 11. 리스부채 만기구조 주석 — COUNTA 버킷팅 기법

`리스부채만기구조_2503` (72행 × 101열)

### 11.1 구조
```
        C      D      E      F      G      H       I
      1개월  3개월  6개월  12개월  3년    5년    총계
부동산 66,603 131,063 172,098 369,888 1,349,120 552,952 = 2,641,723 (천 단위 아님, 원)
동산   13,867  27,734  38,784  65,662   137,133  21,455 =   304,635
```

### 11.2 산출 기법 — **월별 캘린더 + COUNTA**
```
계약별 행에 N열~DA열 = 2024_1 … 2029_12 월별 컬럼을 깔고,
해당 월에 리스료가 발생하면 값을 채운다.

C15 (1개월 이내)  = COUNTA(AS15)      * $L15   ← L15 = 고정리스료(월)
D15 (1~3개월)     = COUNTA(AT15:AU15) * $L15
E15 (3~6개월)     = COUNTA(AV15:AX15) * $L15
F15 (6~12개월)    = COUNTA(AY15:BD15) * $L15
G15 (1~3년)       = COUNTA(BE15:CB15) * $L15
H15 (3~5년)       = COUNTA(CC15:CZ15) * $L15
```

> 💡 **왜 훌륭한가**
> - 계약 종료월 이후 셀을 비워두면 **COUNTA가 자동으로 0을 세므로 만기가 자동 반영**된다.
> - 리스료 인상 계약(`K12` 메모: "매년3%인상")은 월별 셀에 직접 금액을 넣어 `SUM(AY12:BD12)` 방식으로 처리 → **두 방식 혼용 가능**.
> - 결산 기준월이 바뀌면 **버킷 경계 열 참조만 한 칸씩 밀면 된다.**

### 11.3 ⚠️ 반드시 구분할 것 — 미할인 vs 할인

| 구분 | 금액 | 용도 |
|---|---|---|
| **미할인 리스료 총액** | 2,641,722,696 (부동산) | **유동성위험 주석**(1107.39), 만기구조표 |
| **리스부채 장부금액** | 미할인 총액 - 현재가치할인차금 | BS 표시금액 |

> **가장 흔한 실수**: 만기구조 주석 총계를 BS 리스부채와 대사하려다 안 맞아서 헤매는 것. **둘은 원래 다르다.** 차액 = 현재가치할인차금 잔액.

## 12. 리스부채 롤포워드 검증 — 3중 tie-out

`리스부채만기구조_2503` J~M열 + `리스회계결산_2503` Q~R열

```
[부동산]  기초(bs12월) 3,521,026,234
          - 감소 K3 =   830,529,032 + 68,811,634     ← 결산분개 임차료지급+해지
          + 증가 L3 =    16,615,872 + 51,232,272     ← 결산분개 신규/갱신
          = 1월말 M3 = 2,689,533,713
          - 2월 감소 66,602,778 + 2월 증가 18,791,760
          = M4 = 2,641,722,695   ≒  I3 만기구조 총계 2,641,722,696  (1원 차이)
```

**월별 검증 블록** (`리스회계결산_2503` Q38~R42, Q75~R79, Q116~R120):
```
1월: 리스부채증가 R38 = K11+K14+K17           (결산분개 대변 합계)
     리스부채감소 R39 = H32+H3+H8             (결산분개 차변 합계)
```

## 18. 재무활동 부채 조정공시 (K-IFRS 1007.44A) — 미해소 검증

> **관측**: `(기말)` 접미사 + 숨김 처리 = **연차보고서에만 작성**하는 시트로 보인다. 분기 파일에서는 미갱신 상태로 수식만 살아 있어 FALSE를 표시한다.
> **차이 원인 추정**: 기초잔액 `C27 = 1,128,050,438`이 하드코딩이며 전전기 값일 가능성. **확인 필요.**

> 1. **1007.44A 조정공시는 별도 표를 유지해야 한다.** 기초 → 현금흐름 → 비현금(환율·공정가치·기타) → 기말. 파일은 이 형식을 정확히 갖췄다.
> 2. ⚠️ **기말 전용 시트를 분기 파일에 방치하면 FALSE 검증셀이 누적**되어, 진짜 오류 신호와 구분이 안 된다. → **시트 상단에 "기말 전용 / 분기 미작성" 배너를 두거나, 검증셀을 `IF(분기여부, "N/A", 검증식)` 으로 감쌀 것.**
