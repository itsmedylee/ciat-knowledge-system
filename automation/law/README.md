# 법제처 조문조회 (`law-kr`)

법제처 국가법령정보 Open API를 **직접** 호출하는 로컬 MCP 서버다.
위키의 세법·회계 서술을 조문 원문과 대조할 때 쓴다.

> `automation/`은 지식 레이어가 아니다 — ingest·lint 대상에서 제외한다.

## 왜 만들었나

기존 `korean-law` MCP는 제3자 중계서버(`mcp.gomdori.app`)를 경유한다. 2026-08-20·08-22
두 차례 그 서버가 죽어 조문 대조가 통째로 막혔고, `[현행 기준 확인 필요]` 표시가 쌓였다.
게다가 그 서버는 **전달한 `oc` 값을 무시하고 자기 인증키로 조회**한다 —
사무소 OC가 쓰이지 않고, 어떤 조문을 찾아봤는지가 제3자를 거친다.

이 서버는 그 두 문제를 없앤다. **중계 없음 · 사무소 OC 사용 · 외부 의존성 0.**
기존 `korean-law`는 지우지 않았다. 이중화가 목적이다.

| | `law-kr` (이것) | `korean-law` (기존) |
|---|---|---|
| 경로 | 법제처 직접 | gomdori.app 경유 |
| OC | 사무소 것 | 서버 운영자 것 |
| 조회 내역 | 외부로 안 나감 | 제3자 서버 경유 |
| 장애 시 | 법제처가 죽을 때만 | 중계서버가 죽으면 끝 |
| 판례·해석례 | ✅ | ✅ |

## 도구

| 도구 | 용도 |
|---|---|
| `law_search` | 법령·판례·해석례·행정규칙·자치법규 검색 → MST/ID 획득 |
| `law_article` | 조문 본문 (`제23조의2` 같은 자연어 조번호) |
| `law_find` | **법령 본문에서 키워드가 든 조문 찾기** |
| `law_toc` | 조문 목록(조번호 + 제목) |
| `law_precedent` | 판례 본문 (판시사항·판결요지·참조조문) |
| `law_interpretation` | 법령해석례 본문 (질의요지·회답·이유) |

### `law_find`가 핵심이다

**0건이 곧 근거가 된다.** 어떤 규정이 *없다*는 것을 확인할 수 있다.

2026-08-23에 이 도구로 실제 오류를 잡았다 — 위키가 "수증자가 증여자보다 먼저 사망하면
사전증여가 합산 배제된다"를 확정 규정처럼 서술하고 약 4~5억 절세 사례까지 싣고 있었는데,
상증세법 전문에서 `먼저 사망`이 **0건**으로 나와 명문 규정이 없음이 드러났다.

## 직접 쓰실 때 (CLI)

MCP 없이 터미널에서도 됩니다.

```bash
cd "automation/law"

python law.py 검색 상속세및증여세법          # MST 얻기

python law.py 찾기 276123 동거주택           # 키워드로 조문 찾기
python law.py 목차 276123 --키워드 공제      # 조문 목록
python law.py 검색 "부담부증여" --종류 판례
python law.py 판례 <ID>
```

## 설정

**`.mcp.json`** (저장소 루트, 커밋됨) — 이것만으로 등록이 끝난다.

```json
{ "mcpServers": { "law-kr": {
    "type": "stdio", "command": "python",
    "args": ["automation/law/law_mcp.py"] } } }
```

**OC(법제처 인증 ID)** 는 이 순서로 정해진다.

1. 환경변수 `LAW_OC`
2. `automation/law/oc.txt` (한 줄. **gitignore됨** — 커밋되지 않는다)
3. 기본값 `ciatpartners`

바꾸려면 `oc.txt`에 새 OC를 한 줄 적으면 된다.
법제처 OC는 <https://open.law.go.kr> 에서 발급받는다(무료, 이메일 ID 앞부분).

**캐시**: 법령 본문은 `.cache/`에 **하루** 보관한다(gitignore됨).
개정 직후라 최신본이 필요하면 `refresh` 인자를, CLI에선 `--새로`를 쓴다.
지워도 무방하다 — 다시 받는다.

## 고장났을 때

```bash
# 1. 서버 자체가 뜨는가
cd "automation/law" && python law.py 검색 민법

# 2. MCP 프로토콜이 도는가
echo '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' | python law_mcp.py
```

| 증상 | 원인 / 조치 |
|---|---|
| `법제처 API 호출 실패` | 네트워크 또는 법제처 점검. 잠시 후 재시도 |
| `JSON이 아닌 응답` | OC가 유효하지 않을 수 있다. `oc.txt` 확인 |
| 조문이 `찾지 못했다` | 삭제된 조문이거나 조번호 오류. `law_toc`로 목록 확인 |
| Claude가 도구를 못 봄 | Claude Code 재시작. `/mcp`에서 `law-kr` 연결 상태 확인 |
| 한글이 깨짐 | `PYTHONIOENCODING=utf-8` 지정 |

### 조회되지 않는 것 (법제처 범위 밖)

⚠️ **국세청 질의회신(서면질의·사전답변)** — `사전-2020-법령해석법인-0295` 같은 것.
법제처 소관이 아니다 → [국세법령정보시스템](https://taxlaw.nts.go.kr).

⚠️ **국세법령정보시스템 출처 판례의 본문** — 검색으로 사건명·사건번호·ID까지는
나오지만, 법제처 상세 API가 그 판례들은 **HTML(iframe)로만** 제공해 본문을 못 가져온다.
검색 결과에 `⚠️본문조회불가(HTML전용)`로 표시된다. 대법원 출처 판례는 정상 조회된다.
세법 판례는 상당수가 국세법령정보시스템 출처이므로, **사건번호를 확보한 뒤
국세법령정보시스템에서 본문을 확인**하는 흐름이 된다.

## 원칙

- **조문이 안 나오면 실패로 처리한다.** 추측해서 채우지 않는다.
  모든 오류 메시지가 그 점을 명시한다.
- 조회 결과에는 항상 **시행일자**가 붙는다. 위키에 옮길 때 기준시점을 함께 적는다.
- 확정한 사실은 `✅ YYYY-MM-DD 조문 검증 완료`로, 못 한 것은
  `[현행 기준 확인 필요]`로 남긴다 (CLAUDE.md 인용 규칙).
